# 微调实验结果：Chinese-CLIP ViT-B-16（2026-10-18）

> 本次微调把中文图文检索的 test R@1 从 **37.37 → 58.67**（+21.30），mean_recall 从 **63.53 → 81.55**。
> 本文件是这次实验的正式记录，改动前后不要覆盖它；新实验另建文件。

## 1. 结论

| 指标 | 预训练基线 | 微调 epoch3 | 绝对提升 | 相对提升 |
|---|---:|---:|---:|---:|
| R@1 | 37.37 | **58.67** | +21.30 | +57.0% |
| R@5 | 70.77 | 89.08 | +18.31 | +25.9% |
| R@10 | 82.44 | 96.90 | +14.45 | +17.5% |
| mean_recall | 63.53 | **81.55** | +18.02 | +28.4% |

评测口径：官方 `cn_clip/eval/` 三件套，test 划分 934 条，文搜图 top-10，候选池 934。

## 5. 训练过程

耗时约 **6 分钟**（12:27:43 加载完权重 → 12:33:51 存完最后一次）。

| 时间点 | Valid Loss | Image2Text Acc | Text2Image Acc |
|---|---:|---:|---:|
| epoch1 @ 150 步 | 0.2225 | 91.77 | 91.25 |
| epoch1 @ 235 步 | 0.1963 | 93.33 | 92.19 |
| epoch2 @ 300 步 | 0.2056 | 91.87 | 92.50 |
| epoch2 @ 450 步 | 0.1571 | 94.58 | 93.44 |
| epoch2 @ 470 步 | 0.1543 | 94.90 | 93.75 |
| epoch3 @ 600 步 | 0.1444 | 94.48 | 94.27 |
| **epoch3 @ 705 步** | **0.1403** | **94.69** | **94.48** |

valid loss 单调下降、准确率持续上升，**未见明显过拟合**；到第 3 轮末仍在改善（说明 3 轮尚未练满）。

⚠️ 这里的 Acc 是 **batch 内 32 个候选**的口径，与第 1 节 934 候选的 R@K 不可直接比较。

## 7. 与官方脚本的差异

官方模板用 `torch.distributed.launch` + DDP，本机 NCCL 的 `all_reduce` 会永久挂死，
因此改用 `NoDDP` + `--skip-aggregate`。补丁在
[`scripts/finetune/patches/`](../../scripts/finetune/patches/)：

```bash
bash scripts/finetune/patches/apply.sh
```

原因、3 处改动的改前/改后代码、`module.` 前缀为什么必须保留、换机器如何重新施加，
全部见 [`04-Chinese-CLIP补丁说明.md`](04-Chinese-CLIP补丁说明.md)。

## 9. 局限与使用限制

1. **test 集已经使用过一次**（本次）。后续任何再训练/调参只能看 valid，不能再拿 test 作选型依据；
   否则"提升 21 个点"这个结论会被污染。
2. **评测文本与训练同分布**：test 的文本同样由四属性模板生成，所以提升里含"适配模板写法"的成分；
   换成真实用户自由输入，增益会小于这组数字。
3. **R@10 已接近饱和**（96.90），后续对比请用 R@1 或 mean_recall。
4. **候选池只有 934**，不能与官方 MUGE（十万级）的 R@1 横比。
5. **检索索引已接入**：用 `epoch3.pt` 建立的索引在 `data/index_data_finetuned/`（9 类 9,393 条），
   预训练权重生成的 `data/index_data/` 保留作基线。查询时不需要手动指定权重，
   `search_category_index.py` 会从索引注册表自动读取。**尚未做**端到端召回对比（见第 11 节）。
6. 未使用数据增强（`--use-augment`），未使用 `accum_freq` 模拟大 batch——两项都仍有余量。

## 11. 检索索引接入

用微调权重重新编码全部商品，建立独立索引，与预训练权重的索引并存：

| | 预训练基线 | 微调后 |
|---|---|---|
| 权重 | `models/chinese_clip/clip_cn_vit-b-16.pt` | `experiments/2026-10-18_bs32_lr1e-5/checkpoints/epoch3.pt` |
| 索引目录 | `data/index_data/` | **`data/index_data_finetuned/`** |
| 类别 / 条数 | 9 类 / 9,393 条 | 9 类 / **9,393 条** |
| 用途 | 基线对比 | 线上检索 |

分项条数：鞋 3219 / 水杯 2016 / 包 1291 / 男装 999 / 运动服 668 / 女装 357 / 手机壳 300 /
厨房用品 279 / 家居用品 264，合计 9,393，各类 `errors` 均为 0。

建索引命令：

```bash
python scripts/retrieval/build_category_index.py \
  --checkpoint data/processed_data_retrieval/experiments/2026-10-18_bs32_lr1e-5/checkpoints/epoch3.pt \
  --output-dir data/index_data_finetuned \
  --overwrite
```

三条约束：

1. 权重路径写进 `data/index_data_finetuned/index_registry.json` 的 `model.checkpoint`，
   每个类别的 `build_report.json` 也各记一份，可追溯；
2. 查询和评测脚本**从注册表自动读取**该权重，不要手动传 `--checkpoint`，否则可能出现
   "建索引用 A、查询用 B" 的静默错配（不报错，结果全乱）；
3. 两套索引的向量不在同一空间，不能混用；脚本会检查注册表，权重不一致时直接报错。

**待做**：用同一套查询集（`evaluation/retrieval/results/runs/deepseekv4_1_flash_pilot_20261018/inputs/queries.csv`
与 `qrels.csv`）分别在两套索引上评测，得到端到端召回的新旧对比。

注意：那组 pilot 查询的来源商品约 80% 落在 train 划分，所以对比结果只能算"同分布下的相对提升"，
不能当独立泛化证据（见第 9 节第 1 条）。
