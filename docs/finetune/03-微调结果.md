# 微调实验结果：Chinese-CLIP ViT-B-16（2026-10-18）

> 本次微调把中文图文检索的 test R@1 从 **37.37 → 58.67**（+21.30），mean_recall 从 **63.53 → 81.55**。
> 本文件是这次实验的正式记录，改动前后不要覆盖它；新实验另建文件。

## 1. 结论

| 指标 | 预训练基线 | 微调 epoch3 | 绝对提升 | 相对提升 |
|---|---:|---:|---:|---:|
| R@1 | 37.37 | **58.67** | +21.30 | +57.0% |
| R@5 | 70.77 | 89.08 | +18.31 | +25.9% |
| R@10 | 82.44 | 96.90 | +14.45 | +17.5% |
| mean_recall | 63.53 | **81.55** | +18.02 | +28.4% |

评测口径：官方 `cn_clip/eval/` 三件套，test 划分 934 条，文搜图 top-10，候选池 934。

## 7. 与官方脚本的差异（重要，避免下次重踩）

官方 `muge_finetune_vit-b-16_rbt-base.sh` 用 `torch.distributed.launch` + DDP。**本机跑不通**：
WSL2 环境下 NCCL 的 `all_reduce` 会永久挂死（`init_process_group` 正常，第一次集合通信卡死；
`NCCL_P2P_DISABLE`、`NCCL_SHM_DISABLE`、`NCCL_CUMEM_ENABLE=0` 均无效）。

解决方式（已写入 `Chinese-CLIP/` 内的本地补丁，该目录不入库）：

| 改动 | 内容 |
|---|---|
| 新增 `cn_clip/training/no_ddp.py` | `NoDDP` 包装器：保留 `model.module` 与 `module.` state_dict 前缀，供单卡使用 |
| `cn_clip/training/main.py` | `world_size > 1` 才建 DDP，否则用 `NoDDP` |
| `cn_clip/training/train.py` | 验证阶段的 4 次 `all_reduce` 只在多卡时执行 |
| 启动方式 | `python` + 手动设 `RANK/WORLD_SIZE/LOCAL_RANK/MASTER_*`，不用 `torchrun`；加 `--skip-aggregate` |

`NoDDP` 保存出的 ckpt 仍带 `module.` 前缀，官方 `extract_features.py`（第 157 行自动剥离）可直接加载——已实测。

另有两个环境坑：
- `torchrun` 从 2.6 起自带 `--logs-specs`，会与训练脚本的 `--logs` 前缀冲突报 `ambiguous option`；
- 镜像内无 `git`/`curl`，源码用 Python 下载 tarball（`codeload.github.com`）解压。

**3 处改动的完整说明**（改前/改后代码、`module.` 前缀为什么必须保留、换机器如何重新施加）见
[`04-Chinese-CLIP补丁说明.md`](04-Chinese-CLIP补丁说明.md)。

## 9. 局限与使用限制

1. **test 集已经使用过一次**（本次）。后续任何再训练/调参只能看 valid，不能再拿 test 作选型依据；
   否则"提升 21 个点"这个结论会被污染。
2. **评测文本与训练同分布**：test 的文本同样由四属性模板生成，所以提升里含"适配模板写法"的成分；
   换成真实用户自由输入，增益会小于这组数字。
3. **R@10 已接近饱和**（96.90），后续对比请用 R@1 或 mean_recall。
4. **候选池只有 934**，不能与官方 MUGE（十万级）的 R@1 横比。
5. **本权重尚未接入检索链路**：`scripts/retrieval/encoder.py` 只支持 `load_from_name()`，
   要加载本 ckpt 需新增 `--checkpoint` 参数（待办）。
6. 未使用数据增强（`--use-augment`），未使用 `accum_freq` 模拟大 batch——两项都仍有余量。
