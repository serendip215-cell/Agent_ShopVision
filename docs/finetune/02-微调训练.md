# GPU 主机微调训练说明

> 微调流程第 2 步（第 1 步数据准备见 [`01-数据转换脚本说明.md`](01-数据转换脚本说明.md)）。
>
> **2026-10-18 已实跑完成**，结果见 [`03-微调结果.md`](03-微调结果.md)。本文保留原始设计说明，
> 但与实际做法有三处不同，照做前先读 [`scripts/finetune/README.md`](../../scripts/finetune/README.md)：
>
> | 本文原写法 | 实际做法 |
> |---|---|
> | `bash scripts/finetune/run_finetune.sh`（`torch.distributed.launch` + DDP） | 本机 NCCL 集合通信挂死，改用 `scripts/finetune/run_train_single_gpu.sh`（`NoDDP` + `--skip-aggregate`） |
> | 日志文件 `out.log` | 实际是 `out_<UTC 时间戳>.log` |
> | 输出目录 `<名称>` | 统一为 `RUN_ID`，如 `experiments/2026-10-18_bs32_lr1e-5/` |
>
> 实测环境是 **Windows + WSL2 + Docker 容器（Linux）**，不是 Mac + 远程 GPU 主机。

微调训练需要 NVIDIA GPU（CUDA）。本仓库实测环境：WSL2 内的
`pytorch/pytorch:2.7.1-cuda12.8-cudnn9-devel` 容器 + RTX 5060 Ti 8GB，单卡 3 轮约 6 分钟。

## 要准备的东西(汇总)

| 资源 | 大小 | 从哪来 | 放到哪 |
|---|---|---|---|
| 本仓库代码 | 小 | `git clone` | 任意位置,如 `~/Agent_ShopVision` |
| Chinese-CLIP 官方代码 | ~7MB | `git clone https://github.com/OFA-Sys/Chinese-CLIP.git` | 仓库根目录下 `Chinese-CLIP/` |
| 预训练权重 | ~719MB | 本地上传,或官方发布页下载 | `models/chinese_clip/clip_cn_vit-b-16.pt` |
| LMDB 训练数据 | ~1.2GB | 本地上传(本地已生成好) | `data/processed_data_retrieval/datasets/ShopVision/` |

以上 4 项就位后,一条命令开训。输出(新权重)写在:
`data/processed_data_retrieval/experiments/<RUN_ID>/checkpoints/`（本次为 `2026-10-18_bs32_lr1e-5`）

## 一、环境准备

```bash
# 1. 拉仓库
git clone <仓库地址> Agent_ShopVision && cd Agent_ShopVision

# 2. clone Chinese-CLIP 官方代码(不入库,每个环境都要自己拉)
git clone https://github.com/OFA-Sys/Chinese-CLIP.git

# 3. 建 Python 环境并装依赖(需要 CUDA 版 PyTorch)
conda create -n cn-clip python=3.9 -y && conda activate cn-clip
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
pip install -r Chinese-CLIP/requirements.txt
```

## 二、放预训练权重

权重文件不进 git(约 1.5GB),每个环境自己准备。

- 如果本地已有(本仓库 `models/chinese_clip/clip_cn_vit-b-16.pt`),直接上传:

```bash
# 在本地机器上执行(把 用户名/主机地址 换成实际的)
scp models/chinese_clip/clip_cn_vit-b-16.pt \
    用户名@主机地址:Agent_ShopVision/models/chinese_clip/
```
- 如果没有,从官方发布页下载 ViT-B-16 权重:
  https://github.com/OFA-Sys/Chinese-CLIP#%E4%B8%8B%E8%BD%BD
  (选 `CN-CLIP_ViT-B-16`,下载后重命名/放到下面的路径)

最终必须在这个位置:

```
models/chinese_clip/clip_cn_vit-b-16.pt
```

## 三、放训练数据

LMDB 数据集不进 git(约 1.2GB),从本地上传:

```bash
# 在本地机器上执行(把 用户名/主机地址 换成实际的)
rsync -avP data/processed_data_retrieval/datasets/ShopVision \
    用户名@主机地址:Agent_ShopVision/data/processed_data_retrieval/datasets/
```

传完后在 GPU 主机上检查,应该看到这个结构(数量必须一致):

```
data/processed_data_retrieval/datasets/ShopVision/
├── lmdb/
│   ├── train/{imgs,pairs}     # 7,520 条
│   ├── valid/{imgs,pairs}     #   939 条
│   └── test/{imgs,pairs}      #   934 条
├── train_imgs.tsv / train_texts.jsonl
├── valid_imgs.tsv / valid_texts.jsonl
├── test_imgs.tsv  / test_texts.jsonl
└── id_mapping.csv
```

> 如果 GPU 主机上有原始图片和 `products.csv`,也可以直接在 GPU 主机上重新生成
> (先跑 `scripts/build_retrieval_dataset.py` 再跑官方 `build_lmdb_dataset.py`),
> 但一般不推荐,从本地上传更省事。

## 四、开始训练

**实际使用的命令**（容器内，已封装成脚本）：

```bash
tr -d '\r' < /workspace/scripts/finetune/run_train_single_gpu.sh > /tmp/run.sh && bash /tmp/run.sh
```

从 WSL 宿主机发起：

```bash
docker exec -it shopvision bash -c "tr -d '\r' < /workspace/scripts/finetune/run_train_single_gpu.sh > /tmp/run.sh && bash /tmp/run.sh"
```

脚本会自动 `cd` 到仓库根目录，路径按根目录写死，在任意目录执行都可以。

> 原设计是 `bash scripts/finetune/run_finetune.sh`（官方 `torch.distributed.launch` + DDP）。
> 该方式在本机 WSL2 环境下会因 NCCL `all_reduce` 挂死，**不要使用**；原因与替代方案见
> [`scripts/finetune/README.md`](../../scripts/finetune/README.md)。

预计耗时：单卡 3 轮 / 705 步，RTX 5060 Ti 上约 6 分钟（V100/A100 更快）。

## 五、训练中怎么看进度

日志实时打印在终端，同时写入：

```
data/processed_data_retrieval/experiments/<RUN_ID>/out_<UTC时间戳>.log
```

例如本次：`experiments/2026-10-18_bs32_lr1e-5/out_2026-10-18-12-27-38.log`。

重点看（注意实际日志里打的是 i2t/t2i 准确率，不是 R@1/R@5/R@10）：

```
Validation Result (epoch 1 @ 150 steps) | Valid Loss: 0.222458 | Image2Text Acc: 91.77 | Text2Image Acc: 91.25
```

- **loss 是否稳步下降**；
- **每次 validation 的 Valid Loss 与两项 Acc 是否改善**（这是 batch 内 32 候选口径，与最终 `evaluation.py` 的 R@K 不可比）。

想后台跑、断开终端也不怕：

```bash
nohup bash /tmp/run.sh > /tmp/train.log 2>&1 &
tail -f /tmp/train.log
```

## 六、训练完后做什么

输出目录（`RUN_ID` 一次实验一个）：

```
data/processed_data_retrieval/experiments/<RUN_ID>/
├── checkpoints/
│   ├── epoch_latest.pt    <- 最后一次保存的权重（和最后一个 epoch 相同）
│   ├── epoch1.pt
│   ├── epoch2.pt
│   └── epoch3.pt          <- 跑 3 个 epoch 时取这个
├── out_<UTC时间戳>.log
└── params_<UTC时间戳>.txt
```

**把 `epoch3.pt`(或 `epoch_latest.pt`)下载回本地**,交给下一步:
用它重建检索索引(新目录,不覆盖旧索引),然后由队友做新旧对比评估。

## 七、关键参数(要调就改脚本里这几行)

| 参数 | 当前值 | 说明 |
|---|---|---|
| batch size | 32 | OOM 就改成 16,并在启动参数加 `--grad-checkpointing` |
| 学习率 | 1e-5 | 已比官方 5e-5 小;loss 不降或验证指标下降就改 5e-6 重跑 |
| epoch | 3 | 数据量小,先跑 3 轮;验证集指标还在涨就改 5 |
| context_length | 52 | 官方默认,不用动 |
| 初始权重 | `models/chinese_clip/clip_cn_vit-b-16.pt` | 从预训练权重出发微调 |

改完参数建议把脚本里的 `name=` 也改一下(比如改学习率后改成 `..._lr5e-6`),
避免新一次训练的输出覆盖上一次的结果。

## 八、常见问题

- **CUDA out of memory**:batch size 改 16 + 加 `--grad-checkpointing`
- **找不到 LMDB**:确认第三节的目录结构,训练脚本读的是 `.../ShopVision/lmdb/train` 和 `.../lmdb/valid`
- **找不到权重**:确认 `models/chinese_clip/clip_cn_vit-b-16.pt` 存在
- **Chinese-CLIP import 报错**:脚本已把 `Chinese-CLIP/` 加进 PYTHONPATH;确认第 2 步 clone 了官方仓库
