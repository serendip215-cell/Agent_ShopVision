## 一、本组口径

任务书用 CIFAR-10 / 技术博客文本举例，本组沿用实验 1–4 对象：**电商商品图文 + Chinese-CLIP 双塔检索**。实验五在此基础上加 Agent 层：LLM 只做意图解析与工具调用，商品事实全部来自自有 9,393 条库与双塔接口，不编造。

闭环：实验1 数据 → 实验2 微调（LoRA）→ 实验3 优化（量化）→ 实验4 API（双塔接口）→ **实验5 Agent**（LangChain 调实验4 API）。

## 五、报告口径红线

- 任务是模板举例，本组按电商图文 + 双塔 Agent 口径写，不照抄 CIFAR-10 / ResNet。
- Agent 的 LLM 只做意图解析，商品事实来自双塔接口；不声称模型编造商品。
- 延迟/准确率数字标清后端（CPU/GPU）与机器；量化 4-bit 目标≤5 秒、10 轮准确率≥90%。
- 未做部分如实注明，不声称已测。

### image 能力归属（澄清：不在 5.3 验收线，是实验4 能力 + 5.4 直调）

5.2 微调数据**只教了 `text_search` 一种工具调用**（`tool_call` 样本 15 条全为 `text_search`），故模型不会裸调 `image_search`/`match`。项目里含 image 的文件是实验3 检索索引/质检（`image_embeddings.npy` 等），**无图片类 LLM 工具训练数据**。因此：

- Agent 结构化工具白名单 **仅 `text_search`**，与微调数据严格对齐；
- `image_search`（图搜/判类）、`match`（图文一致）是**实验4 后端现成接口**，由 **5.4 前端/规则降级直调实验4 `/api/v1/image`、`/api/v1/match`**，不走 LLM 工具调用；
- **例外（需重新决策）**：若组内后续要求「LLM 也能调 image/match」，则需补 `image_search` 工具 + 补微调数据样本并重新微调 5.2 模型，属新增范围，当前不做。
