## 2. 结论怎样写进报告

建议使用下面这段作为速度与精度的核心结论：

> 在训练机的同硬件配对测试中，ONNX Runtime 的 TensorRT 后端将 Chinese-CLIP 图像编码器的 batch=1 中位延迟从4.59ms降至1.94ms，将 batch=32 从50.43ms降至23.84ms，对应加速2.366倍和2.115倍，延迟降低57.73%和52.73%；记录吞吐分别提升136.58%和111.52%。在同一934条文本、934张候选图片的双塔文搜图测试中，PyTorch-FP32与TensorRT-FP16的R@1分别为58.5653%和58.1370%，净差为−0.4283个百分点，满足本轮≤1pp的一致性要求。速度计时只覆盖图像塔forward，不能据此宣称完整检索请求取得相同加速。

以下细节应保留：

- 正式测速数据采用预热10次、计时20次的单轮中位数；不要照旧计划写成计时50次或多轮均值。
- ORT-CPU的两个batch加速为1.062×/0.991×；ORT-CUDA为1.097×/0.933×，均未达到40%延迟降低目标。图表保留不成功的对照。
- 934条指标是精确配对文搜图；132条是旧索引的AI试点标签评测，不能混为一个测试集。
- TensorRT的净命中差约相当于4条，但没有逐样本变化明细，不能写“仅4条查询发生变化”。
- 参数与理论FLOPs没有因后端加速而减少。42.63GFLOPs只统计MatMul/Conv，文本长度52。
- 文本塔ONNX文件大小为389.58/194.97MiB；导出报告被最后一次文本塔执行覆盖，不能据此报告双塔ONNX总大小。
- 本轮没有TRT分类别输出。图04展示“后端×整体R@K差值”，图06展示9类别FP32基线，不把INT8损失当成TRT损失。
- 当前凭证只给出请求provider及实际会话provider列表；本轮沿用已认可的后端记录，不新声称获取了逐节点TensorRT执行比例。

## 4. 其他开发者怎样复现

在仓库根目录，使用已激活的Python环境；已有pytorch环境可复用。若是Conda，务必先正常激活，确保数值库DLL可用；无需创建另一个训练环境。

    conda activate pytorch
    python -m pip install -r evaluation/retrieval/requirements-report.txt
    python evaluation/retrieval/code/evaluate_acceleration.py --run-id exp3_report_my_run

Conda不是必须条件，普通Python虚拟环境安装上述依赖也可以；Linux另需Noto Sans CJK SC字体。依赖只有numpy、matplotlib、Pillow，不要求torch/onnxruntime/TensorRT。

PowerShell启动入口：

    .\evaluation\retrieval\scripts\run_exp3_evaluation.ps1 -RunId exp3_report_my_run

全部路径从脚本定位到仓库根目录解析，不绑定D盘或某个人的Python安装位置。默认输出到 evaluation/retrieval/results/runs/<run-id>/，拒绝无意覆盖已有结果。重新生成同一个run需显式加 --overwrite / -Overwrite。

只重绘：

    python evaluation/retrieval/code/render_acceleration_charts.py --run-dir evaluation/retrieval/results/runs/exp3_inference_acceleration_20261025

从归档快照产生新run：

    python evaluation/retrieval/code/evaluate_acceleration.py --config evaluation/retrieval/results/runs/exp3_inference_acceleration_20261025/inputs/evaluation_config.json --run-id exp3_report_from_snapshot

后续如果队友提供新结果，应复制来源配置并改sources、runtime_groups、accuracy_groups和primary_group，再用新run-id执行。脚本自动计算阈值，不把本次“通过”写死。来源schema必须与现有训练机脚本一致；如果方法换成别的架构或数据集，先确认评测口径再替换输入。

逻辑测试：

    python -m unittest discover -s evaluation/retrieval/tests -p test_acceleration.py -v

8项测试覆盖正确的配对比值、provider回退拒绝、CPU/GPU跨设备拒绝、线程不对齐拒绝、精度基线/候选池匹配、阈值包含等号、零延迟拒绝、相对路径限制。它们验证复算逻辑，不重新审核数据集或代替模型实测。

## 5. 需要本人完成的现场行为

文档要求“至少一人现场演示/录屏”，这项需要持有训练机与模型文件的人执行。当前电脑缺少实验二微调epoch3.pt与双塔ONNX，本轮没有录制视频，也没有把预训练权重冒充微调权重。

### 5.1 准备条件

1. 在训练机进入仓库根目录，准备 docs/optimize/00-方案与口径.md 中对应的epoch3.pt、ShopVision测试集。
2. 使用队友已验证的环境：torch 2.7.1+cu128、onnx 1.23.2、onnxruntime-gpu 1.22.0、TensorRT 10.x cu12。具体库路径设置见 scripts/optimize/README.md，不能仅因可导入就认定GPU后端已生效。
3. 确认TRT provider实际可用，并在正式录屏前完成引擎构建与预热。首次构建可能需5–20分钟；本轮稳态延迟不含这段冷启动时间。
4. 若重跑，选择新run-id保存测量，不覆盖已归档的源结果。

### 5.2 可复现的模型侧命令

以下是在训练机已激活模型环境、位于仓库根目录时运行的命令；本轮交付只提供操作步骤，没有在本机执行这些命令。

    export PYTHONPATH="$PWD/Chinese-CLIP"
    python scripts/optimize/export_onnx.py --run-id exp3_demo_20261025 --tower visual --precision fp32
    python scripts/optimize/export_onnx.py --run-id exp3_demo_20261025 --tower visual --precision fp16
    python scripts/optimize/export_onnx.py --run-id exp3_demo_20261025 --tower text --precision fp32
    python scripts/optimize/export_onnx.py --run-id exp3_demo_20261025 --tower text --precision fp16
    python scripts/optimize/bench_runtime.py --run-id exp3_demo_20261025 --device cuda --precision fp16 --provider TensorrtExecutionProvider --batch 1 32 --warmup 10 --iters 20
    python scripts/optimize/eval_onnx.py --run-id exp3_demo_20261025 --precision fp16 --provider TensorrtExecutionProvider --batch-size 32 --baseline docs/optimize/runs/2026-10-23_exp3-quant/accuracy/test_fp32.json

导出脚本当前的export_report_<precision>.json会被同run中最后导出的塔覆盖；本轮已将这一限制写入报告。现场展示时分别说明是哪一个塔，不凭最后的文本塔报告宣称双塔体积。若出现实际provider回退，不能将回退后的结果记成TRT实测。
