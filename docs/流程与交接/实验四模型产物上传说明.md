## 一、要传的文件

| 文件 | 训练机路径 | 大小 | 必/选 |
|---|---|---:|---|
| `visual_fp32.onnx` | `data/optimize/2026-10-24_exp3-speed/onnx/` | ≈329 MB | **必需** |
| `text_fp32.onnx` | 同上 | ≈390 MB | **必需** |
| `visual_fp16.onnx` | 同上 | ≈165 MB | 可选（GPU 后端用） |
| `text_fp16.onnx` | 同上 | ≈195 MB | 可选（GPU 后端用） |

- FP32 两个是本地 CPU 后端直接加载的，**必须传**。
- FP16 两个只在 GPU / TensorRT 上跑时用；方便就一起传，不方便可先跳过。
- **不用传 `epoch3.pt`**（2.1 GB，含优化器动量），实验四不重训，用不到它。

## 二、上传前：确认文件还在

```bash
ls -la data/optimize/2026-10-24_exp3-speed/onnx/
```

看到 `visual_fp32.onnx`、`text_fp32.onnx` 就是还在，往下走第三节。
文件不在了（机器重置过、删过），跳到第六节重跑导出。

## 三、生成 sha256（第四步回填要用）

```bash
python -c "import hashlib,pathlib; d=pathlib.Path('data/optimize/2026-10-24_exp3-speed/onnx'); [print(f.stat().st_size, hashlib.sha256(f.read_bytes()).hexdigest(), f.name) for f in sorted(d.glob('*.onnx'))]"
```

把输出的「字节数 + sha256 + 文件名」三列留着。

## 四、上传到 GitHub Release

Release tag 统一用 **`assets-exp3-20261025`**。

**方式 A：网页（最省事）**

1. 打开 https://github.com/serendip215-cell/Agent_ShopVision/releases
2. 点 **Draft a new release**
3. **Choose a tag** 填 `assets-exp3-20261025` → Create new tag
4. Release title 填「实验三模型产物（双塔 ONNX）」
5. 把上面「要传的文件」拖进附件框
6. 点 **Publish release**

**方式 B：命令行（训练机装了 gh 并已 `gh auth login`）**

```bash
gh release create assets-exp3-20261025 \
  --repo serendip215-cell/Agent_ShopVision \
  --title "实验三模型产物（双塔 ONNX）" \
  --notes "供实验四后端加载：visual_fp32.onnx / text_fp32.onnx（+ 可选 fp16）" \
  data/optimize/2026-10-24_exp3-speed/onnx/visual_fp32.onnx \
  data/optimize/2026-10-24_exp3-speed/onnx/text_fp32.onnx
```

（要传 fp16 就在命令末尾再加两个文件路径。）

## 五、上传后：回填三个数

把第四节每个文件的「文件名 / 字节数 / sha256」贴回来（对话里发即可），用来写 `assets_manifest.json`。

顺手自证一下下载端能拿到（不必登录）：

```bash
curl -sIL https://github.com/serendip215-cell/Agent_ShopVision/releases/download/assets-exp3-20261025/visual_fp32.onnx | grep -i content-length
```

能返回大小（≈344,000,000 量级）就是上传成功且公开可下。

## 六、如果文件没了，重跑导出

前提：训练机上有 `epoch3.pt`、`Chinese-CLIP/` 能 import、装了 `onnx` / `onnxruntime`。

```bash
# 图像塔
python scripts/optimize/export_onnx.py --tower visual --precision fp32
# 文本塔（必须两个塔都导；仓库里只留了文本塔凭证，别以为只需文本塔）
python scripts/optimize/export_onnx.py --tower text --precision fp32
```

产物会写到 `data/optimize/2026-10-24_exp3-speed/onnx/`，每次约 20 秒。导完回到第三节。

> 注：`export_onnx.py` 每次都覆盖同名 `export_report_<precision>.json`，所以仓库里 `export_report_fp32.json` 只记了最后导出的文本塔——这是正常的，不代表图像塔没导。

## 七、还要记录一件事：Chinese-CLIP 版本

文本塔 ONNX 只吃 `input_ids`/`attention_mask`，分词靠 `cn_clip.clip.tokenize`。**分词必须和导出时同一版本**，否则同一句话切出来的 id 不同、结果对不上。请在训练机上取一下 commit 并回填：

```bash
git -C Chinese-CLIP rev-parse HEAD
```

## 八、红线

- 只传第一节列的 4 类 ONNX 文件，**不要**把整个 `data/optimize/` 或 `epoch3.pt` 拖上去。
- 单个附件 < 2 GB；这四个都远低于上限。
- 传完**自己下一次校验 sha256 与上传前一致**，别只信「上传成功」提示。
- 这些文件是我们自己训练的产物，仓库 public、谁都能下，没问题；不要把任何含密钥/隐私的文件一起传。
