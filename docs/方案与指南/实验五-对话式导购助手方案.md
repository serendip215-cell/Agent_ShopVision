**主题**：大模型 Agent 部署训练。目标是基于实验 1–4 成果，形成「数据 → 微调 → 框架集成 → 部署交互」完整闭环。

**实验环境**
- 硬件：CPU≥16 核、内存≥64GB、GPU（分布式中可选多 GPU 加速微调）。
- 软件：PyCharm / Anaconda（Python 3.12+），PyTorch≥2.5，Transformers≥4.40，Accelerate≥0.27，PEFT≥0.10；OpenAI SDK（DeepSeek）、modelscope、zai SDK / OpenAI 兼容（ChatGLM）、Ollama；LangChain≥1.0；FastAPI≥0.130（延续实验4）、Docker≥24.0、Redis≥7.2（任务队列）；React 18+（复用实验4）、Ant Design Pro。
- 关联依赖：实验1 文本数据集、实验2 LoRA 代码、实验3 量化工具、实验4 后端 API。

**四阶段任务**
| 阶段 | 模块 | 内容 |
|---|---|---|
| 阶段1 环境与数据准备 | 5.1.1 环境部署 / 5.1.2 微调数据准备 | 部署大模型环境；从实验1 `text_data.json` 抽 100 条，用「指令-输入-输出」格式生成 `agent_finetune_data.json`，复用实验1 清洗逻辑 |
| 阶段2 模型选择与微调 | 5.2.1 选型与评估 / 5.2.2 LoRA 微调 | 根据工具调用能力、显存和推理成本选择基座模型（DeepSeek-V4-Flash/V4.1-Flash、GLM-5/5.3、Qwen3.5 等）；独立设计 LoRA 参数，使用 SFTTrainer 训练；完成基线与微调后对比、验证集评测和模型交接 |
| 阶段3 Agent 框架集成 | 5.3.1 核心逻辑 / 5.3.2 推理测试 | LangChain 将实验4 的图像/文本分类 API 封装为工具，`create_agent` 初始化；单轮 + 多轮推理测试 |
| 阶段4 部署与测试 | 5.4.1 FastAPI 暴露 / 5.4.2 前端集成 / 5.4.3 端到端 | Agent 服务封装为 API（`/api/v1/agent/chat`）；实验4 React 项目新增 `AgentChat.tsx`；场景1 图像分类(猫)、场景2 文本分类、场景3 多轮对话 |

**重点**：前后端数据流（query-response 与工具调用统一 `user/agent/tool_calls` 字段）、API 规范（沿用 v1、错误码复用 400/500 + 新增 404 ToolNotFound）、异常处理（前端友好提示、后端 3 次重试 + 日志）。

**难点**：跨平台兼容（前端 Flexbox+媒体查询、后端 JSON 转义 + CORS 放行 3000/8001）；分布式协调（Redis+Celery 工具调用队列、推理请求排队）；训练资源（4-bit 量化 + 8 步梯度累积降显存）。

**报告要求**：①组成员构成与分工；②「实验1 数据→实验2 微调→实验3 优化→实验4 API→实验5 Agent」闭环架构图 + 各阶段技术复用点；③Agent 性能评估（工具调用准确率，10 轮目标≥90%；文本/图像平均响应延迟，量化前后对比）；④问题与解决方案（显存不足、工具调用失败、跨域等；对比实验2 小模型微调与大模型微调差异）。

**验收口径示例**：量化 4-bit 下 Agent 响应目标≤5 秒；10 轮工具调用准确率≥90%；三浏览器 + 移动端适配；模拟 API 超时前端「请重试」提示。

## 1. 背景：京东 AI 购做了什么

京东「AI购」是对话式购物 App，底座为京东自研言犀大模型，并与京东主站商品、外卖系统打通。它的功能与背后依赖：

| 功能 | 背后需要什么 |
|---|---|
| 对话式购物（“帮我点常喝的奶茶”） | LLM 意图理解 + 工具调用 + 订单/商家系统 |
| 灵感空间、每日一惠 | 个性化推荐 + 促销/价格数据 |
| 爱购瀑布流 | 用户行为画像 + 推荐系统 |
| 外卖下单 | 商家、配送、支付链路 |
| 穿搭灵感 + AI 试穿 | 生成式试穿模型（扩散模型）+ 商品图 |
| 降价提醒 | 价格历史库 |
| 商品对比（六维度） | 结构化商品参数（静音、重量、续航等） |

结论：这是**一整个电商 App**，不是单点功能；照搬不在课程范围，也没有对应数据与交易系统。

## 2. 我们有什么、缺什么

| 能力 | 现状 | 判断 |
|---|---|---|
| 文搜商品 | `POST /api/v1/text`，9 类 9,393 条库 | ✅ 可直接用 |
| 拍图找同款 | `POST /api/v1/image` | ✅ 可用，但只在自有闭集库里检索 |
| 图文一致性 | `POST /api/v1/match` | ✅ 现成 |
| 对话式导购 | 无 LLM | ⚠️ 可外接 Qwen / DeepSeek API |
| 灵感卡片 | 无 | ⚠️ 可做静态卡片 → 跳检索，半天量级 |
| 商品对比 | 只有品牌/颜色/材质/类目/标题 | ⚠️ 只能做浅层对比，六维度参数我们没有 |
| 个性化推荐 | 仅 localStorage 浏览历史 | ⚠️ 只能按历史重排，不是推荐系统 |
| 降价提醒 | 无价格数据 | ❌ 做不了 |
| 外卖/下单/支付 | 无商家与交易系统 | ❌ 做不了，也不该做 |
| AI 试穿 | 双塔不生成图像 | ❌ 需换扩散模型 + GPU，是另一个项目 |

## 3. 本项目定位

**基于现有 Chinese-CLIP 双塔检索的对话式导购助手**：用户用自然语言说需求，LLM 只负责“听懂 + 调工具”，商品事实一律来自我们自己的 9,393 条库与三个检索接口。

一句话边界：**LLM 不编商品，模型不生成事实，所有商品都能在库里指到源数据。**

## 4. 范围

### 做

1. 对话输入框 + 多轮对话（保留最近 N 轮）。
2. 意图解析：找商品 / 找相似图 / 判类别 / 图文是否匹配 / 对比商品。
3. 工具调用：白名单，只允许调已有接口与新增的对比工具。
4. 结果渲染：复用现有商品卡片；对比用表结构展示我们真有的字段。
5. 无 LLM 时的降级：规则解析（关键词 + 类目词）也能走通检索。

### 不做

- 下单、支付、配送、库存。
- 价格监控、促销计算。
- AI 试穿、图像生成。
- 全站商品搜索、开放类目。
- 让 LLM 生成商品标题/属性/描述。

## 5. 架构（目标形态）

```text
浏览器 Chat UI
   │  自然语言
   ▼
意图层：LLM（Qwen / DeepSeek API）或规则降级
   │  只输出结构化意图（工具名 + 参数）
   ▼
工具层（白名单）
   ├─ POST /api/v1/text     文搜商品
   ├─ POST /api/v1/image    拍图找同款 / 判类
   ├─ POST /api/v1/match    图文一致性
   └─ compare(items)        新增：按 items.csv 字段做浅层对比
   │
   ▼
商品库：data/index_data_finetuned（9 类 9,393 条）
   │
   ▼
回复：模板化文案 + 商品卡片；禁止模型自由编造商品信息
```

要点：

- LLM 的输出**只作为工具调用参数**，不作为商品内容直接展示。
- 后端代理 LLM key，不把 key 放前端；接口失败时回退规则解析。
- 所有工具调用的返回都要带 `item_id` 与 `local_image_path`，保证可追溯。

## 6. 分阶段

| 阶段 | 内容 | 产出 |
|---|---|---|
| P0 | 聊天框 + 文本检索 + 规则解析 | 能“说需求 → 出商品”，不接 LLM 也能演示 |
| P1 | 接 LLM，意图 → 工具调用；支持图搜、判类、图文匹配 | 多意图可用 |
| P2 | 商品对比（类目/颜色/材质/品牌/标题/相似度）+ 历史重排 | 对比表与个性化排序 |
| P3 | 灵感卡片（静态预设查询）、对话历史 | 演示完整度 |

P0 先落地，保证离线可答辩；LLM 只做增强，不做单点依赖。

## 7. 风险与红线

| 风险 | 应对 |
|---|---|
| LLM API 费用 / 网络 / key 管理 | 后端代理、限额、超时；规则降级 |
| 模型幻觉编造商品 | 只渲染工具返回的商品；回复模板化 |
| 提示注入诱导越权工具调用 | 工具白名单 + 参数校验，不接受任意 URL/SQL |
| 闭集 9 类，用户问库外商品 | 明确回复“库里没有”，不假装有 |
| 属性稀疏，对比维度不足 | 只对比真实字段，不伪造参数 |
| 延迟叠加（LLM + 检索） | 先检索后润色，或并行；首字响应优先 |
| 评测无标准 | 固定 10~20 条演示脚本，逐条记录命中/失败 |

## 8. 验收口径

- 10 条固定对话脚本，至少 8 条能返回库内真实商品；
- 每个返回商品都有 `item_id`，能在 `/item-images` 找到原图；
- 断网 / 无 key 时规则模式仍能完成文搜与图搜；
- 不出现库内不存在的商品名、价格、参数；
- 答辩时能说清：LLM 只做意图解析，检索与事实来自双塔 + 索引。

## 9. 待定

- LLM 选型（Qwen / DeepSeek）与调用方式（后端代理 vs 前端直连）。
- 对话历史存哪（内存 / localStorage / 后端会话）。
- 多轮槽位设计（类目、颜色、top_k 的继承与覆盖）。
- 是否给对比工具单独开后端接口，还是前端聚合。
