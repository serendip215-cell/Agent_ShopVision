## 一、任务书读完的结论

### 1.1 阶段 1：六个任务，至少做一个

| 任务 | 内容 | 我们做不做 |
|---|---|---|
| 3.1.1 模型量化 | CV 塔静态量化（需校准数据）、NLP 塔动态量化；选做 GPTQ/AWQ/SmoothQuant/KV Cache INT8 | ✅ **主线** |
| 3.1.2 模型剪枝 | CV 结构化通道剪枝（L1 准则）、NLP 注意力头 + 神经元剪枝；剪枝率 5–30% 扫描；剪后微调 3–5 epoch | ✅ **推荐加分**（报告第 4 条需要） |
| 3.1.3 模型蒸馏 | ResNet-50→ResNet-18、BERT-base→DistilBERT | ❌ 不做（我们没有更大的同构教师模型；实验二的 LoRA 分支也不适用） |
| 3.1.4 推理加速 | CV 走 TensorRT、NLP 走 ONNX Runtime，层融合 / 动态批处理 | ✅ **必做**（报告第 3 条硬性要求） |
| 3.1.5 资源占用 | 权重稀疏存储 + 内存复用、嵌入层 INT16、动态加载 | ⬜ 部分并入（体积/显存/峰值内存本来就要报），稀疏存储与动态加载不做 |
| 3.1.6 鲁棒性 | PGD 对抗训练、文本扰动 | ⬜ 选做加分（成本低，能补「鲁棒性」那一维） |

### 1.2 阶段 2：优化与部署验证（任务书标「选做」）

- 3.2.1 计算图优化：转 ONNX + ONNX Runtime，**目标提速 20%+、精度误差 ≤0.5%**；
- 3.2.2 硬件加速：GPU 走 TensorRT、CPU 走 OpenVINO，对比不同硬件的速度与精度。

⚠️ 与报告要求有张力：阶段 2 标「选做」，但**报告第 3 条硬性要求「不同优化方法（ONNX/TensorRT/OpenVINO）的速度提升对比」**。稳妥做法：ONNX / ONNX Runtime 必做，TensorRT 与 OpenVINO 尽量都试（都是 pip 可装）。

### 1.3 报告要求四条（硬性，逐条对应到我们的产出）

| 报告要求 | 我们怎么给 |

## 二、任务书 → 本项目的映射（先看这张表，别照抄任务书）

任务书是按「ResNet-18（分类）+ DistilBERT（分类）」写的通用指导；我们实验二做的是 **Chinese-CLIP ViT-B/16 中文图文检索**。逐条替换：

| 任务书写法 | 我们的对应 | 说明 |
|---|---|---|
| ResNet-18（CV 模型） | **图像编码器 ViT-B/16** | 双塔的视觉那一路 |
| DistilBERT（NLP 模型） | **文本编码器 RoBERTa-wwm-ext-base-chinese** | 双塔的文本那一路；原模型共约 188M 参数 |
| Top-1 准确率 | **Recall@1** | 检索任务里 R@1 就是「Top-1 命中率」，R@5 对应 Top-5 |
| `./data/dataset/test.csv` | 实验一 8:1:1 划分出的 **test 934 条**（来源：清洗数据 9,393 条） | 另加端到端口径：固定 132 查询 / 1325 标签（`evaluation/retrieval/results/runs/deepseekv4_1_flash_pilot_20261018/inputs/`） |
| 校准数据（训练集子集） | 实验一训练集前 500 条 | 任务书五、难点里的建议，照做 |
| FLOPs 减少 30%（剪枝目标） | 量化**不改 FLOPs 计数**，改位宽与带宽 | 表里同时给「FLOPs（剪枝后才变）」和「等效位宽 / bit-ops（量化后变化）」，别把两者混为一谈 |
| ResNet 的残差结构 | ViT-B/16 的残差连接 + LayerNorm + 多头注意力 | 报告第 4 条的关联分析按这个写 |
| 异构设备（低功耗 CPU / 边缘设备，可选） | 训练机容器内的 CPU vs GPU；**非训练机（RTX 3050 Ti 4GB）可选充当边缘设备** | 若要真跑，只需传量化后的 ONNX（比 `.pt` 小），不必传原始权重 |

**精度口径统一**：所有「ΔAccuracy」在本项目一律写 **ΔR@1（百分点）**，两组测试口径都跑：模型级 934 条、端到端 132 查询。

## 五、训练机流程与命令

容器 `shopvision`，仓库在容器内 `/workspace`。命令从 WSL 宿主机发起；`.sh` 脚本要 `tr -d '\r'` 清 Windows 换行符（见 `scripts/finetune/README.md`）。

### 5.1 P0 环境（任务书要求 PyTorch 2.4+ / ONNX 1.17+ / ORT 1.20+ / TensorRT 10.0+ / OpenVINO 2025.1+）

```bash
wsl -d Ubuntu-22.04
docker exec -it shopvision bash -lc "cd /workspace && git pull && export PYTHONPATH=/workspace/Chinese-CLIP && \
  python -c \"import torch,timm,faiss,cn_clip.clip as c;print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name())\""

# 加速与量化工具（缺什么装什么；onnxruntime-gpu 与 tensorrt 走 CUDA 12，容器已带）
docker exec -it shopvision bash -lc "pip install \"onnx>=1.17\" \"onnxruntime-gpu>=1.20\" \"openvino>=2025.1\" && \
  python -c \"import onnx, onnxruntime, openvino; print(onnx.__version__, onnxruntime.__version__, openvino.__version__)\""
docker exec -it shopvision bash -lc "pip install -U \"bitsandbytes>=0.46\""      # 4-bit 组
```

- `torch.cuda.is_available()` 必须 `True`；`cn_clip` 靠 `PYTHONPATH` 指向官方代码，**不要再 pip install cn_clip**。
- TensorRT：`pip install tensorrt`（10.x，配套 CUDA 12）。装不上就如实退成 ORT+OpenVINO 两路，报告写明。
- 缺 `faiss`/`timm`：`pip install -r /workspace/scripts/retrieval/requirements.txt`。

### 5.2 P1 要写的代码

| # | 文件 | 改什么 |
|---|---|---|

| 5 | `scripts/retrieval/search_category_index.py` | 同上 |
| 6 | `scripts/optimize/bench_inference.py` | 新建：体积、参数量、FLOPs（`torch.utils.flop_counter.FlopCounterMode`）、峰值显存、启动时间、单样本延迟、批量 32 吞吐 → JSON |

| 9 | `scripts/optimize/prune_towers.py` | 新建（P6 剪枝用）：L1 通道剪枝 + 注意力头剪枝，输出剪后权重与 FLOPs |
| 10 | `docs/scripts/gen_figures_exp3.py` | 新建：误差热力图 + 权衡曲线（在非训练机跑，只吃 json） |

3 份配置 `configs/retrieval_exp3_{fp16,int8,nf4}.json` 从 `configs/retrieval.json` 复制，各改两处：

```jsonc
{
  "build":  { "output_dir": "data/index_data_exp3_nf4",
              "checkpoint": "data/processed_data_retrieval/experiments/2026-10-18_bs32_lr1e-5/checkpoints/epoch3.pt",
              "quant": "nf4" },
  "search": { "index_dir":  "data/index_data_exp3_nf4", "quant": "nf4" }
}
```

**同源原则（最要命的一条）**：查询编码器与索引向量必须同一权重、同一精度。评测脚本从索引的 registry 取编码器，`build` 时必须把 `quant` 写进 registry，否则会拿 FP16 编码器去搜 INT8 索引——**不报错，但指标全废**。

### 5.9 七个坑

1. registry 里的权重路径必须能解析，否则评测读不到编码器；
2. 建索引与评测的 `quant` 必须一致（同源原则，错了不报错但全废）；
3. INT8 动态量化是 CPU 路径，`--device cuda` 加不上；
4. 5060 Ti 是 sm_120，4-bit 要新版 `bitsandbytes`，TensorRT 要 10.x；
5. 先 smoke（手机壳 300 条）再全量 9,393 张；
6. ONNX 导出图像塔与文本塔要**分开**（两者输入形态不同），文本塔给动态序列长度；
7. `data/index_data/鞋/鞋/` 是重复的整份鞋索引（27MB，被 git 跟踪），对比新旧索引前先删。

## 九、风险与退路

| 风险 | 退路 |
|---|---|
| 4-bit / TensorRT 在 sm_120 上装不上 | 退成 FP16 vs INT8 + ORT/OpenVINO，报告写明缺了哪路和原因 |
| ViT 静态量化算子不支持（LayerNorm/GELU） | 图像塔改动态量化或 FP16，文本塔保持动态量化；报告写清取舍 |
| INT8 全量 9,393 张太慢 | 先出体积/延迟结论，精度那栏补跑；或抽样并在报告写明抽样口径 |
| ONNX 导出文本塔报动态轴错误 | 固定序列长度导出（实验一模板文本长度固定，影响可控） |
| 剪枝后精度掉太多 | 缩小剪枝率（任务书扫描 5–30% 本就是找拐点），把拐点当结论 |
| 非训练机没有权重 | 不用传原始权重；做异构验证时传量化后的 ONNX（体积小得多） |
| 不同精度向量混用 | 一律整类重建索引（仓库 README 已写死「换模型必须重新提向量」） |
