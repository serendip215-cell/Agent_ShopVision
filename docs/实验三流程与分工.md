## 一、为什么选量化（六个任务对比）

| 任务 | 适配度 | 理由 |
|---|---|---|
| **3.1.1 量化** | ⭐ **选它** | 实验二的权重、双塔、固定验证集、评测脚本全现成；任务书要的「CV 塔静态量化 + NLP 塔动态量化」正好对应我们的图像塔 + 文本塔 |
| 3.1.2 剪枝 | 次选（降为可选加分） | 要 L1 通道剪枝 + 注意力头剪枝 + 剪后微调 3–5 轮，相当于再训一次，是六个里第二重的活 |
| 3.1.3 蒸馏 | 不做 | 需要一个更大的同构教师模型（我们没有），还要训 10–15 epoch，直接排除 |
| 3.1.4 推理加速 | 顺带做 | 不改参数量，填不了报告第 2 条的「压缩前后对比表」；但 ONNX 导出是量化权重的另存格式，成本极低 |
| 3.1.5 资源占用 | 不做 | 稀疏存储 + 内存复用 + 动态加载，工程量大、与检索链路耦合差、收益说不清 |
| 3.1.6 鲁棒性 | 不做 | PGD 对抗训练 + 微调 5 epoch，要重训，且偏离「轻量化」主题 |

选量化的四条硬理由：

1. **指标口径天然对齐**：任务书要 Top-1 准确率损失，我们的 **R@1 就是 Top-1 命中率**，ΔR@1 直接当 ΔAccuracy，不用造新指标。
2. **目标数字轻松达标**：模型约 188M 参数，FP32 约 750MB，INT8 后约 188MB——**正好是任务书那句「FP16→INT8 体积减少 75%」**。剪枝要凑 FLOPs −30% 得反复扫比例。
3. **报告第 2 条它全包**：参数量、模型大小（文件字节）、精度损失、**误差分布热力图**（9 类别 × 各精度组的 ΔR@1，分类别汇总现成）。
4. **退路最多、最省学时**：FP16 基线零成本，INT8 是 PyTorch 内置，4-bit 装不上就退回两组照样达标；剪枝/蒸馏要重训，出问题就卡死。

## 二、任务书 → 本项目的映射（别照抄任务书）

任务书是按「ResNet-18（分类）+ DistilBERT（分类）」写的通用指导；我们实验二是 **Chinese-CLIP ViT-B/16 中文图文检索**：

| 任务书写法 | 我们的对应 | 说明 |
|---|---|---|
| ResNet-18（CV 模型） | **图像编码器 ViT-B/16** | 双塔的视觉那一路 |
| DistilBERT（NLP 模型） | **文本编码器 RoBERTa-wwm-ext-base-chinese** | 双塔的文本那一路；模型共约 188M 参数 |
| Top-1 准确率 | **Recall@1** | R@1 即 Top-1 命中率，R@5 对应 Top-5 |
| `./data/dataset/test.csv` | 实验一 8:1:1 划分出的 **test 934 条**（来自清洗数据 9,393 条） | 另加端到端口径：固定 132 查询 / 1325 标签 |
| 校准数据（训练集子集） | 实验一训练集前 500 条 | 任务书五、难点里的建议，照做 |
| FLOPs 减少 30%（剪枝目标） | 量化**不改 FLOPs 计数**，改位宽与带宽 | 表里同时给「FLOPs」和「等效位宽 / bit-ops」，别混为一谈 |
| ResNet 的残差结构 | ViT-B/16 的残差连接 + LayerNorm + 多头注意力 | 报告第 4 条的关联分析按 ViT 写 |

**精度口径统一**：所有「ΔAccuracy」一律写成 **ΔR@1（百分点）**；两组测试口径都跑：模型级 934 条、端到端 132 查询。

3 份配置 `configs/retrieval_exp3_{fp16,int8,nf4}.json` 从 `configs/retrieval.json` 复制，各改两处：

```jsonc
{
  "build":  { "output_dir": "data/index_data_exp3_nf4",
              "checkpoint": "data/processed_data_retrieval/experiments/2026-10-18_bs32_lr1e-5/checkpoints/epoch3.pt",
              "quant": "nf4" },
  "search": { "index_dir":  "data/index_data_exp3_nf4", "quant": "nf4" }
```

**同源原则（最要命）**：查询编码器与索引向量必须同一权重、同一精度。评测脚本从索引的 registry 取编码器，`build` 时必须把 `quant` 写进 registry，否则会拿 FP16 编码器去搜 INT8 索引——**不报错，但指标全废**。

### 5.9 七个坑

1. registry 里的权重路径必须能解析，否则评测读不到编码器；
2. 建索引与评测的 `quant` 必须一致（同源原则；错了不报错，但指标全废）；
3. INT8 动态量化是 CPU 路径，`--device cuda` 加不上；
4. 5060 Ti 是 sm_120，4-bit 要新版 `bitsandbytes`；TensorRT 要 10.x；
5. 先 smoke（手机壳 300 条）再全量 9,393 张；
6. ONNX 导出图像塔与文本塔要**分开**，文本塔给动态序列长度；
7. `data/index_data/鞋/鞋/` 是重复的整份鞋索引（27MB，被 git 跟踪），对比新旧索引前先删。

## 九、风险与退路

| 风险 | 退路 |
|---|---|
| 4-bit 装不上（sm_120） | 退成 FP16 vs INT8 两组，报告写明原因 |
| ViT 静态量化算子不支持（LayerNorm/GELU） | 图像塔改动态量化或 FP16，文本塔保持动态量化；报告写清取舍 |
| INT8 全量 9,393 张太慢 | 先出体积/延迟结论，精度那栏补跑；或抽样并在报告写明抽样口径 |
| ONNX 导出文本塔报动态轴错误 | 固定序列长度导出（实验一模板文本长度固定，影响可控） |
| TensorRT / OpenVINO 装不上 | 只报 ONNX Runtime 一路，报告写明「未做及原因」 |
| 非训练机没有权重 | 不用传原始权重；做异构验证时传量化后的 ONNX（体积小得多） |
| 不同精度向量混用 | 一律整类重建索引（仓库 README 已写死「换模型必须重新提向量」） |
