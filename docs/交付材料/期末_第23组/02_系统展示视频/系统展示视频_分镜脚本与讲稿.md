3. 方案 §8 的验收口径（10 轮工具调用 ≥90%、响应 ≤5 秒）无法录制，不要念。
4. [API约定.md](../../../../webapp/API约定.md) 的 `/image`、`/text` 示例缺了实际返回的 `attributes`、`items`、`query_category`、`query_score`、`topk[].confidence`；`/match` 实际还返回 `image_type`。录屏以界面为准，文档差异另补，不要在现场解释。

## 二、逐句口播讲稿

> 总控：全片 798 字，按 220 字/分钟约 3 分 38 秒。重录请整镜重录，不要在一句中间剪辑。
> 「/」表示换气停顿；加粗词在字幕里同步高亮。

### 镜 1｜0:00–0:12｜43 字｜约 12 秒

这是一套商品多模态检索系统。一句描述，或者一张照片，都能找到相似的商品。下面用四个真实场景演示。

### 镜 2｜0:12–0:31｜68 字｜约 19 秒

首页是工作台。左侧三个指标全部来自真实数据：**九千三百九十三条检索索引**、**九个商品类别**、**五百一十二维向量**。下方按类别浏览商品，整套系统只靠这一条索引工作。

### 镜 3｜0:31–1:03｜119 字｜约 33 秒

先看图像分类。点一张白色运动鞋示例图，识别立刻开始。**不到一秒**返回结果：类别是**鞋**，细分类**运动鞋**，颜色**白色**，材质**网布**，置信度**百分之十四点七**。这是九个类别归一化后的最高概率，不是模型拍脑袋。右侧给出备选类别，以及最相似的四件商品，第一件与上传图几乎完全相同，相似度**一点零零**。

### 镜 4｜1:03–1:30｜98 字｜约 27 秒

第二个场景，用一句话搜商品。点示例「黑色双肩包」，系统把这句话编码成向量，在全库**九千多条索引**里检索。返回结果全部落在**包**这一类，榜首是 everlane 双肩包，相似度**零点四九**；下方用九个类别的颜色条展示命中分布，说明检索并没有预先限定类别。

### 镜 5｜1:30–2:07｜137 字｜约 37 秒

第三个场景，图文匹配。点「一致示例」，系统同时跑**两条独立链路**：图像塔把白鞋图片编码成向量，文本塔把「白色运动鞋」编码成向量。两边各自判决：图像塔判**鞋**，细分类**跑步鞋**；文本塔也判**鞋**，细分类**高帮运动鞋**。细分类并不相同，页面中间写明**只比对顶层大类**。结论区给出绿色的一致。下方五条证据来自文本塔的检索结果，用来解释这个判断。

### 镜 6｜2:07–2:34｜97 字｜约 27 秒

再看反例。换成「双肩包」，图片不变。这次图像塔仍然判**鞋**，文本塔判**包**，结论立刻变成橙色不一致。注意两边的细分类本来就不一样，但判定不看细分类，**只看大类是否相同**。这就是双塔模型的核心：两个编码器分开预测，最后做一次一致性核对。

### 镜 7｜2:34–3:01｜98 字｜约 27 秒

系统也支持补录新商品。在商品入库页上传一张白鞋，不用人工填表：模型直接建议类别**鞋**、细分类**运动鞋**、颜色**白色**、材质**网布**，并给出三个类别的打分。确认后写入上传库，检索时自动并入，不需要重建静态索引。演示时停在这一步，不改动数据。

### 镜 8｜3:01–3:17｜60 字｜约 16 秒

每次运行都会记进运行记录，可以导出复核。系统状态页列出**模型后端、索引规模、九个类别的条目数**，以及全部接口和错误码，方便验收时逐项核对。

### 镜 9｜3:17–3:38｜78 字｜约 21 秒

一句话总结：图像和文本各自编码到**同一个向量空间**，检索、匹配、入库都围绕这一条索引。下一步，实验五会在这三个接口之上加一层 **Agent**，用多轮对话自动调用它们，完成从描述到成交的导购闭环。

## 三、演示流程要点（录一遍就能过）

演示顺序 = 图像分类 → 文本检索 → 图文匹配（一致、不一致）→ 商品入库建议 → 记录与状态。这是把方案里「图像分类 / 文本分类 / 多轮对话」三场景改造后的可执行版本：第三场景用图文匹配替代，多轮对话只在片尾口播出现。

### 场景 1：图像分类（`/image`）

- 精确输入：点上传卡下方**第 1 个示例缩略图**（白色运动鞋），点击即自动识别，不用再点【开始识别】。
- 预期画面：类别 **鞋**；细分类 运动鞋、颜色 白色、材质 网布；置信度环 **14.7%**；备选依次 运动服、男装；相似商品 4 行，首行「小白鞋男鞋透气跑步鞋」**1.000**。
- 不点：批量按钮「+」、更换图片后的其他示例（避免多路径翻车）。

### 场景 2：文本检索（`/text`）

- 精确输入：点示例胶囊 **「黑色双肩包」**（点击即自动检索）；若胶囊没触发，就手动输入同样五个字后按 Enter。
- 预期画面：类别 **包**；5 条结果全部为包；榜首 `everlane 双肩包` **0.493**；顶部 9 类分布条仅「包」着色。
- 不要改 top_k、不要限定类别，保持默认 5 /「全部类别」，结果最稳。

### 场景 3：图文匹配（`/match`）——替代方案里的「多轮对话」

- 3a 一致：点【一致示例】（白鞋图 + 「白色运动鞋」）。预期：图像塔 鞋 / 跑步鞋 / 14.7%，文本塔 鞋 / 高帮运动鞋 / 12.0%，结论绿色「一致」，证据 5 行。
- 3b 不一致：点【不一致示例】（白鞋图 + 「双肩包」）。预期：图像塔 鞋 / 跑步鞋 / 14.7%，文本塔 包 / 双肩包 / 11.9%，结论暖橙「不一致」，证据 5 行全为包。
- 两个按钮都会自动填图与文本并直接提交，不要中途改文本，避免加载示例图与请求并发。
- 多轮对话**不要**用任何界面假装；如评委问，答「实验五规划中，正片片尾以架构图说明」。

### 场景 4：商品入库建议（`/admin`）

- 精确输入：上传 `webapp/frontend/public/samples/sample-shoe.jpg`，等建议区出现即停。
- 预期画面：「模型建议」卡显示建议类别 **鞋**、相似度 **1.0002**；候选三类 鞋 **1.0002** / 运动服 **0.7458** / 男装 **0.7424**；右侧表单预填细分类 运动鞋、颜色 白色、材质 网布，并提示「参考值，不是模型识别」。
- **不要点【确认入库】**：确认会写 `data/webapp.db` 并复制图片到上传目录，属于改数据。若确实要演示重复检测，先备份 `data/webapp.db`，录完还原。

### 场景 5：运行记录与系统状态（`/history`、`/status`）

- 前提：先完成场景 1–3，运行记录才会有 3–4 条；记录是本浏览器本地数据，换浏览器/清缓存会空。
- 预期画面：记录列表显示模式、耗时、状态；状态页显示 `onnx`、类目条目数、接口清单、错误码。
- 索引目录一栏若出现本机绝对路径，后期裁切或模糊。

## 四、录制清单

### 4.1 需要提前准备的素材

- 4 张示例图（页面内置，也各存一份到桌面备用）：`samples/sample-shoe.jpg`、`samples/sample-bag.jpg`、`samples/sample-bottle.jpg`、`items/12445240159.jpg`
- 备用商品图（`webapp/frontend/public/items/` 任选 2 张，如 `12423222225.jpg`、`12433779747.jpg`）
- 架构字卡源文件（4 个色块 + 3 条箭头，导出 1920×1080 PNG）
- 字幕文件（SRT，按第二节逐段切分）

### 4.2 启动与预热（录制前 10 分钟）

1. 后端（必须用项目虚拟环境，PATH 里没有全局 Python）：
   `cd webapp/backend` → `.\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000`
2. 前端：`cd webapp/frontend` → `npm run dev`（默认 5173，`/api` 已代理到 8000）。
3. 自检：浏览器打开 `http://localhost:8000/api/v1/health`，确认 `"backend": "onnx"`、`"model_loaded": true`、`"dimension": 512`、`"categories"` 共 9 个。
4. 预热：先手动跑一遍 图像分类 → 文本检索 → 图文匹配一致 → 不一致，把模型与静态索引读进内存；实测预热后单次约 0.4 秒。
5. 关闭所有通知（Windows 专注助手 / 微信 / 邮件），关闭 DevTools、终端窗口、GitHub 页面。

### 4.3 录屏参数

- 分辨率 1920×1080，30 或 60 fps；浏览器窗口 1440×900，缩放 100%。
- 隐藏书签栏与扩展图标；只留一个标签页，地址栏允许出现 `localhost:5173`。
- 鼠标高亮开启（录屏软件自带），点击时停顿 0.5 秒再动，方便后期配字幕。
- 系统声音关闭，只录口播；口播另轨录音，后期对齐。

### 4.4 字幕与配乐

- 字体：思源黑体 / 微软雅黑，28–32 px，白字 + rgba(0,0,0,.55) 底衬；关键词用系统主色 `#5fa8b0`。
- 位置：底部安全区，单行不超过 22 个汉字；数字与单位前后各留一个空格（如 `9,393 条`）。
- 配乐：无版权钢琴/环境底噪，音量 -18 dB 左右，片头 2 秒淡入、片尾 3 秒淡出；不要盖过口播。
- 转场只用「淡入淡出」与「直接切」，不要用花哨转场与缩放。

### 4.5 必须避免暴露的信息

- `/status` 页的索引绝对路径（可能显示 `E:\人工智能\AI\Agent_ShopVision\...`）：裁掉或高斯模糊。
- 终端、资源管理器、编辑器里的项目路径与 Windows 用户名 `Zzx`。
- GitHub 账号、提交记录、其他仓库地址。
- 运行记录导出的 JSON 里的本机路径与文件名。
- 其他成员姓名（除片头「第 23 组」外一律不出现；如需分工字幕，先征得本人同意）。
- 邮箱、微信、系统通知弹窗。
