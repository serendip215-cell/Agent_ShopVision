## 第 4 章 · 图文匹配（1:55–2:45，口播 205 字）

**操作**：左侧导航点「图文匹配」（`/match`）；先点**一致示例**，双塔卡出现后停 2 秒特写，再下滑到证据表；回顶部点**不一致示例**，结论区停留 2 秒
**画面要点（一致）**：左「图像塔」鞋/跑步鞋/14.7%，右「文本塔」鞋/高帮运动鞋/12.0%，中间「各自判类」虚线徽标，底部绿色「一致」
**画面要点（不一致）**：图像塔仍鞋，文本塔变包/双肩包/11.9%，结论变橙「不一致」，证据表全为包
**字幕**：`两条独立链路` `只比顶层大类`

**口播**：
第三个功能：图文匹配，这是最能看出双塔架构的一页。点一致示例——系统同时跑两条独立的链路：图像塔把这张白鞋图编码，文本塔把「白色运动鞋」这句话编码。两边各自判类：图像塔判鞋、跑步鞋；文本塔也判鞋、高帮运动鞋。注意细分类两边并不一样，页面中间明确写着只比对顶层大类，所以结论是绿色的一致。下面五条证据来自文本塔的检索结果，用来说明为什么判一致。

再看反例：图片不动，文字换成双肩包。图像塔还是鞋，文本塔变成包，结论立刻翻成橙色不一致，证据表全部落在包类。系统不会和稀泥——两条链路各自说实话，最后做一次大类核对。这就是双塔「各编各判、再比对」的机制，也是我们跟单塔方案最本质的区别。

## 第 5 章 · Agent 对话（2:45–5:05，口播 480 字）★ 核心章节

**操作分四步，全部在 `/agent` 页**：

**步骤 5.1 首轮文本检索（2:45–3:25）**
操作：左侧导航点「对话导购」（进入 `/agent`）；页面中央有三个快捷提示按钮（找一双白色运动鞋 / 有没有黑色的双肩包 / 推荐一款保温水杯）——点第一个「找一双白色运动鞋」（只填入输入框），再点发送按钮；回复出现后停 3 秒；点开「思考过程」折叠条展开 thinking；鼠标划过商品卡片
画面要点：工具调用标签 `text_search`；回复正文；商品卡片横滑（图/名/类目/相似度）；思考过程折叠条
字幕：`四工具白名单` `text_search` `商品卡片来自真实检索`

口播：
重头戏来了——对话导购 Agent，这是实验五的成果。进入 Agent 页，先点这个快捷提示「找一双白色运动鞋」，再点发送。大家注意上方这个灰色的过渡语，和工具调用标签 text_search——这是模型自己决定调哪个工具、传什么参数，不是预设的脚本。商品卡片里的每一件商品都来自真实的检索接口，模型一个字都不编。点开思考过程，能看到模型这轮的完整决策链。这一轮背后是实验五微调的 Qwen3-4B 模型在输出 JSON 动作，后端执行工具，再把检索结果回喂给模型生成这段点评——两轮流程，一次对话里完成。

**步骤 5.2 多轮槽位继承（3:25–4:05）**
操作：在同一个会话的输入框直接打字「要白色的」→ 发送；回复出现后停 3 秒；再打「有没有 43 码的」→ 发送
画面要点：第二轮 thinking 中出现「沿用上一轮类目」字样；商品仍全部是鞋类
字幕：`槽位继承` `查询合并：运动鞋 白色`

口播：
现在测多轮对话的关键能力——槽位继承。我只打三个字：要白色的，然后发送。如果系统直接拿「白色」去搜，会搜出一堆毫不相关的白色东西；但看后端的处理——思考过程里明确写了沿用上一轮类目，实际检索词被合并成「运动鞋 白色」，返回的卡片全部还在鞋类里。这就是会话槽位在工作：上一轮的类目被记住了。接着再补一句「有没有 43 码的」，属性继续并入同一查询。用户不需要每次都重复说全，像跟真人导购说话一样。

**步骤 5.3 图搜接话（4:05–4:40）**
操作：点输入框下方「上传图片」按钮（PictureOutlined 图标），选一张鞋的商品图（文件选择框画面可剪掉，保留选中后一瞬）；选图后出现「已选 1 张图」提示，点「发送」后停 3 秒（Enter 也能发）
画面要点：图像检索结果进会话；首位相似度 0.9573；图像与文本结果出现在同一条会话流里
字幕：`图搜接话` `真实 ONNX 图像塔 0.9573`

口播：
对话里不只能打字，还能发图。我点上传按钮，传一张鞋的商品图，发送。系统用真实的 ONNX 图像塔对这张图编码检索，首位相似度零点九五七三。关键在于：这张图的结果并入了同一条会话历史——接下来我再用文字提问，Agent 知道我们刚才在聊鞋，不会跑偏。图搜接话，说的就是这个能力。

**步骤 5.4 清空会话（4:40–5:05）**
操作：点输入区旁「清空会话」按钮；弹出的确认框点「清空」；页面回到空会话状态；再发一句「找运动鞋」验证是全新会话（可选，画面够长可省）
画面要点：历史清空；后端同步释放提示
字幕：`DELETE /agent/session/{id}` `30 分钟 TTL + LRU`

口播：
聊完了要能干净退出。点右上角的清空会话，确认之后，前端历史立刻清空，后端同时释放这段会话的存储——不只是界面删掉。就算用户不主动清，会话闲置三十分钟也会自动过期，服务端还有淘汰机制兜底，内存不会无限涨。

## 录制执行要点（照做一遍过）

1. **顺序**：按第 0→7 章顺序一遍录完；单镜说错就整镜重录，不在句中剪辑
2. **每步操作后停 2–3 秒**让结果入画，再开始口播——画面与声音错位是最大翻车点
3. **Agent 页是核心**（占全片 1/3 时长）：录之前确认后端加载了 v4 适配器（启动日志有 `adapter=lora_adapter_v4`、`多轮=True`）；如果后端是规则降级模式，步骤 5.2 的槽位继承**不会生效**，只能拍渲染链路——这种情况在字幕注明「本段为渲染路径验证」，别硬说成端到端
4. **文件选择框画面剪掉**：图像上传/图搜两处，只保留「选中文件后结果出现」的片段
5. **不点【确认入库】**：第 6 章演示停在确认前，不改真实数据
6. **录屏参数**：1080p 30fps，浏览器 1440×900 浅色主题，鼠标移动放慢
7. **字幕口径红线**：`100%` 必须带「规范化后」定语；加速数字必须带「3080Ti 配对测速」；不要出现「AI 生成商品信息」类表述
8. **剪掉可省**：时间不够时优先删 5.3 图搜（−35s）和 5.4 清空（−25s），保留 5.1/5.2——多轮继承是实验五最核心的演示点
