### 1.1 一个必须说明的前提：本机只能跑「规则降级模式」

本机没有 Qwen3-4B 基座权重（`models/models/Qwen--Qwen3-4B-Instruct-2507/snapshots/master` 不存在），后端 `agent_service.py` 探测不到 v4 LoRA 可加载的基座，因此走 `rule_parse` 规则模式。后果有两条，必须写进报告，否则实测结果会被误读：

1. `say`（工具调用过渡语）恒为 `null` —— 只有模型动作才会产出 `say`；
2. 多轮槽位继承不生效 —— `agent_service` 里槽位继承/查询合并都包在 `if self._multi_turn:` 内，而 `_multi_turn` 仅在适配器名含 `v4` 时开启。

所以下面第 4 项（say 展示）和第 3 项（图搜接话的「接话」环节）**只能做渲染路径验证，端到端必须在有 v4 模型的演示机上补测**，补测命令见第五节。

### 3.1 首轮文字检索 + 商品卡片（对应第 5 项）

输入「找一双白色运动鞋」→ 弹题胶囊发送或回车。后端返回 `code:0`，`reply` 列出 5 件，`thinking:["规则模式（未接 LLM）","调用工具：text_search(query=白色运动鞋, top_k=5, category=鞋)"]`，`items` 5 条真实商品（含 `local_image_path`）。

截图两张：`01_首轮检索_回复正文.png` 是气泡正文与 `思考过程`/`工具调用（1）` 折叠区；`01_首轮检索_商品卡片.png` 是横滑商品卡片行（高帮鞋男欧货 46.6% / 真皮y3高帮男鞋 46.6% / 小白鞋男生小码 46.4% / 平底女款老爹鞋 46.4% / 白运动鞋男 学生 46.3%，每张卡片带类别角标与相似度）。

### 3.2 刷新保持

首轮对话后 `Ctrl+R` 刷新。页面重新加载后：用户气泡、助手回复、思考过程、5 张商品卡片全部还在，且「清空会话」按钮由 disabled 变为可用 —— 说明 `session_id` 与历史从 `localStorage` 恢复，不是空状态。

### 3.3 清空释放

点「清空会话」→ 页面回到「还没有对话」空状态，`清空会话` 按钮回到 disabled，同时抓到网络请求：

```
DELETE http://localhost:5173/api/v1/agent/session/7b78b562-43fc-4261-abf1-82ce7c4cfa20   status: ok
```

直接打后端复核同接口：`{"code":0,"result":{"deleted":true},"msg":"ok"}` —— 前端确实通知后端释放了这段会话历史。

### 3.4 图搜接话

点「上传图片」挂载 `webapp/frontend/public/samples/cat-shoe.png`（未发送时截图见 `04a`：图片缩略预览 + 「移除图片」按钮 + 输入框 placeholder 切成「可选：补充一句描述…」+ 发送按钮可用）。发送后后端返回：

- `category: "鞋"`，`similarity: 0.9573`
- 5 条鞋类商品：PUMA CARE OF 男士皮质低帮运动鞋 95.7%、Amazon Brand - Symbol 男士白色运动鞋 92.9%、find. 女士低帮运动鞋 91.7%、红蜻蜓小白鞋女 90.4%、完美关系卫哲同款鞋 89.6%
- `thinking: ["图像塔编码：visual 塔 → 512 维","检索：9 类索引，命中 5 条"]`

即图像塔 + 9 类索引这条链路是真实可用的（真 ONNX 前向，不是占位）。且该轮带 `session_id`，结果追加进同一会话时间线（`04b` 中图搜回复排在文字轮之后）。

**缺口**：图搜之后再发「要白色的」这类省略句时，本机规则模式没有「沿用上一轮类目」，实测落到了「水杯」（截图 `03_多轮追问_规则模式.png`，首条「冰淇凌纸杯 41.9%」）。这不是前端问题，是规则模式下 `_multi_turn=False` 的必然结果；演示机接 v4 后应复测为「仍在鞋类里找白色款」。

### 3.5 say 展示

前端渲染路径已实现：
- `webapp/frontend/src/pages/AgentChat.jsx:429` —— `{message.say && <div className="sv-ag-say">{message.say}</div>}`，即 `result.say` 非空字符串才渲染（`.trim()` 后判空，见 L188/L284）；
- `webapp/frontend/src/styles/global.css:6651` —— `.sv-ag-say` 一行灰字样式，位于气泡上方、不抢正文。

本机因规则模式 `say` 恒 `null`，真实请求不会出现这行灰字。为把「渲染路径」这一层验证掉，在页面内临时替换 `XMLHttpRequest.send` 注入一条带 `say` 的假响应（不改代码、不改后端，刷新即失效），页面如期在气泡上方渲染出灰字过渡语「我刚看了一下品类，先帮你按「鞋」来筛，请稍等。」，见 `06_say渲染路径_注入验证.png`。

因此本项结论拆成两半：**渲染链路 PASS（已截图）**；**「模型真的产出 say」待演示机复测**。报告里请勿把它写成端到端通过。

| 浏览器 | 引擎 | 桌面 1440×900 | 移动 390×844 |
| --- | --- | --- | --- |
| Google Chrome | Blink | `兼容性/chrome_*.png` | `兼容性/chrome_*_390x844.png` |

| Mozilla Firefox | Gecko | **未覆盖** | 未覆盖 |

Firefox 情况要如实写：本机原本未安装；本次尝试用 `winget install Mozilla.Firefox` 静默安装（装出 160.0 并写入了开始菜单快捷方式），但快捷方式指向的 `C:\Program Files\Mozilla Firefox\firefox.exe` 实际不存在 —— 静默安装缺少管理员权限、没有真正落盘，因此**没有拿到任何 Firefox 渲染证据**。留给演示机补测，或由有管理员权限的环境装好后再跑一遍。

覆盖页面：`/agent`（对话导购）、`/`（工作台）。

结论：
- 桌面 1440×900：顶部导航 8 个入口（工作台/图像分类/文本检索/图文匹配/对话导购/商品入库/运行记录/系统状态）完整横排、`Describe & Discover` 大标题与胶囊、会话卡片、输入区布局均正常，无横向溢出；
- 移动 390×844：导航收进汉堡菜单、搜索框收成图标、工作台统计卡改两列、对话页胶囊换行、输入框与「上传图片/发送」按钮堆叠正常；
- Chrome 与 Edge 截图字节级几乎一致（同 Blink 内核，渲染结果可预期一致），说明样式未依赖内核特定行为；
- 一处可优化：移动宽度下推荐问题胶囊横向滚动，第三颗「推荐一款保温水杯」在首屏被裁掉一半，属观感问题，不影响功能。

**取证方式说明**：兼容性截图用 Chrome/Edge 的 CDP `Emulation.setDeviceMetricsOverride` 精确设定视口后 `Page.captureScreenshot`（`--headless=new` + `--window-size` 在本机会被 DPI 缩放吃掉，所以走 CDP）；交互能力验证（打字、上传、点击、刷新、清空）在 Chrome 内置浏览器里真实完成。两条路径合起来才算「三件套」：真实交互 + 多引擎多视口渲染。Firefox（Gecko）一项如实记为「未覆盖」，理由是安装未落地（见上）。

建议在演示机补一次 Firefox 肉眼回归，重点看两处：玻璃化导航的 `backdrop-filter`，以及商品卡片横滑行在 Gecko 下的滚动与滚动条样式。
