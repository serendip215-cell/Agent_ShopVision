## 页面 1 · 项目目标

要点：

1. 目标：把「以图搜图 / 以文搜图」的多模态检索，升级为能听懂自然语言、会调工具的对话导购 Agent；
2. 技术路线：Chinese-CLIP ViT-B-16 双塔 + FAISS 向量检索做商品事实层，Qwen3-4B（QLoRA 微调）只做**意图解析与工具路由**，不生成商品信息；
3. 工程链路：数据 → 微调 → 推理加速 → Web 服务 → Agent → 评测，五个实验层层复用；
4. 全链路可复现：训练凭证、评测 JSON、测量凭证均已入库。

建议配图：`04_项目总结报告/00_实验闭环架构.svg`（SVG→PNG 后使用；内容为实验 1→5 数据模型闭环）

## 页面 2 · 数据集构建

要点：

1. 来源：Amazon 与 MUGE 电商图文数据，覆盖 9 类商品；
2. 清洗流水线：类别整理 → 图片存在性检查 → 非本类剔除 → 颜色/材质/细分类补全 → 描述模板化，每步留 CSV/JSONL 日志；
3. 按 `item_id` 哈希切分 train/valid/test = 7,520 / 939 / 934，同一商品的多图不会跨集合（防泄漏）；
4. 训练文本与检索索引文本使用同一模板 `build_product_text`，避免分布不一致。

建议配图：`实验三_第23组/结果图表/06_九类别基线分布.png`（9 类样本分布）

## 页面 3 · 双塔微调（实验二）

要点：

1. 基座 Chinese-CLIP ViT-B-16，LoRA 微调图文双塔，对比学习对齐 512 维向量空间；
2. 效果（test 934 对）：R@1 37.37% → 58.67%，R@5 89.08%，R@10 96.90%；
3. 三组对照：零样本基线 / 未清洗直训 / 清洗后微调，证明清洗数据是涨点主因；
4. 微调后用 epoch3.pt 重编码全库并重建 FAISS 索引。

建议配图：`实验三_第23组/结果图表/03_双塔检索精度.png` + `docs/typ/figs/fig_curves.png`（训练曲线，可选）

口径提醒：这页只讲图文检索指标（R@K），不要与 Agent 工具调用准确率混谈。

## 页面 4 · 推理加速：ONNX + TensorRT（实验三）

要点：

1. 链路：PyTorch → ONNX 导出（图像塔固定 224×224）→ FP16 图层转换 → TensorRT 引擎；
2. 图像塔 batch=1 延迟 4.59 ms → 1.94 ms（**−57.73%**），吞吐 **+136.58%**（同机配对测速，RTX 3080Ti 12GB）；
3. 精度代价：双塔 R@1 相对**同源 FP32 基线** −0.4283pp（任务书阈值 ≤1pp）；
4. batch=32：50.43 ms → 23.84 ms（2.115×），吞吐提升 111.52%。

建议配图：`实验三_第23组/推理加速流水线图.png` + `实验三_第23组/结果图表/01_图像塔延迟对比.png`

口径提醒：基线必须注明机器（同模型边界样本在 5060 与 3080Ti 上会漂移）；TRT 逐样本排名未做，不要声称。

## 页面 5 · Web 系统与 API（实验四）

要点：

1. 架构：React 19 + Antd 前端、FastAPI 接入层、服务层、FAISS 检索索引四层；
2. 接口：同步三接口（`/image` `/text` `/match`）+ 异步任务队列（Celery + Redis）+ Agent 三接口，共 12 个路径，OpenAPI 规范随交付包入库；
3. 编码器可替换：占位 / ONNX 一行配置切换，接口形状不变；
4. 页面：工作台、图像分类、文本检索、图文匹配、商品入库、Agent 对话。

建议配图：`04_项目总结报告/04_系统首页.png`（系统首页）或 `docs/typ/figures/04_图文匹配_并排.png`（图文匹配页）

## 页面 6 · Agent 意图解析与工具调用（实验五 5.1–5.3）

要点：

1. 四工具白名单：`text_search` / `image_search` / `list_categories` / `get_item_detail`，模型输出 JSON 动作，后端执行检索；
2. 两轮流程：模型决策 → 工具执行 → `检索结果：` 回喂 → 生成点评；失败退回规则模板兜底；
3. 运行时防线：工具名白名单 + 编辑距离纠错 + 类目/数量词/查询词参数规范化；
4. v2 评测（10 轮）：**纯模型 9/10 = 90%**，加参数规范化后 **10/10 = 100%**（RTX 3080Ti 与 RTX 5060 8G 两机一致）。

建议配图：`5.3评测截图/5.3工具调用评测截图.png` + `04_项目总结报告/03_工具调用评测_纯模型90%.png`、`03_工具调用评测_混合100%.png`

## 页面 7 · 多轮对话（实验五 5.4）

要点：

1. 会话机制：同会话 8 条历史窗口 + 用户原话摘要（≤6 句）+ 类目槽位继承 + 同类目查询合并；图搜可接话（上一轮文本、本轮图）；
2. 会话管理：`DELETE /agent/session/{id}`、30 分钟 TTL、500 段 LRU；
3. 安全闸：拦截价格/销量断言、纠正主语口误、剥离量词与客套话，商品事实仍只来自检索；
4. v4 多轮评测（40 条对话）：JSON 解析率 **100%**、动作准确率 **90%**、检索命中 **82.5%**、安全通过率 **100%**。

## 页面 8 · 评测结果汇总

要点：

1. 图文检索（test 934 对）：R@1 58.67% / R@5 89.08% / R@10 96.90%；
2. 推理加速（RTX 3080Ti 配对测速）：延迟 −57.73%、吞吐 +136.58%、R@1 误差 0.4283pp；
3. 工具调用（10 轮，v2）：纯模型 90% → 加参数规范化 100%；
4. 多轮对话（40 条）：v3 单轮 JSON 95%/动作 92.5%；v4 多轮 JSON 100%/动作 90%；两版命中均 82.5%、安全均 100%；
5. 5.2 微调总体验证集 75.76% —— **验证集仅 11 条、tool_call 仅 1 条，不具统计意义**，工具调用准确率以 10 轮评测为准。

## 页面 9 · 总结与展望

要点：

1. 已完成：数据 → 双塔微调 → TensorRT 加速 → Web 服务 → Agent 四工具 + 多轮会话的完整闭环，全部带凭证入库；
2. 工程方法沉淀：防泄漏切分、训练/索引同模板、双桶隔离原图、白名单 + 规范化 + 规则降级的安全设计；
3. 已知边界：多轮细节记忆约 2 轮；检索无相似度阈值，库外商品可能误命中；会话状态在进程内存，重启丢失；
4. 展望：扩充人工审核多轮语料（否定条件/价格区间/属性组合）、会话状态迁移 Redis、检索相似度阈值与类别过滤、演示机端到端演练。
