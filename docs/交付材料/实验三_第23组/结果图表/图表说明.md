# 图表说明与写作用法

本目录的所有图均由本轮 tables/ 和 reference_retrieval/ 中的数据生成。每图提供450 DPI RGB PNG 和记录口径的 figure.json；坐标和图注使用中文。

| 图名 | 回答的问题与可引用结论 | 口径与限制 |
|---|---|---|
| [01_图像塔延迟对比](01_图像塔延迟对比.png) | 同硬件配对测量下，主线batch1/32延迟分别降低57.73%/52.73%。 | 仅图像塔 forward；各子图独立横轴，不能跨硬件比较。 |
| [02_图像塔吞吐对比](02_图像塔吞吐对比.png) | 主线batch1/32吞吐分别提升136.58%/111.52%；各后端判定见验收表。 | 沿用来源已四舍五入的吞吐；预处理和引擎构建不计入稳态速度。 |
| [03_双塔检索精度](03_双塔检索精度.png) | 主线R@1相对FP32基线的净差为-0.4283pp。 | 模型级文搜图；不包含自然用户查询的AI标签指标。 |
| [04_后端精度误差热力图](04_后端精度误差热力图.png) | 已提供整体R@K的最大绝对差为0.4283pp。 | 色标固定±1pp；这是后端×指标，不是9类别×TensorRT损失。 |
| [05_模型参数与计算量](05_模型参数与计算量.png) | 双塔共188.26M参数和42.63GFLOPs；后端优化不改变架构。 | batch1；224×224图像、52token；FLOPs仅计MatMul/Conv。 |
| [06_九类别基线分布](06_九类别基线分布.png) | 样本分布不均且各类别基线难度不同，整体指标不能代替分类别检验。 | 完整934候选池中先检索再按类别汇总；不缩小候选池。 |
| [07_模型文件大小](07_模型文件大小.png) | FP16文件约为FP32的一半；文本塔导出报告不能当作双塔ONNX总大小。 | MiB=2^20字节；非峰值显存，也非TensorRT引擎缓存大小。 |
| [08_综合验收仪表盘](08_综合验收仪表盘.png) | 3.1.4判定=True；3.2.1判定=True，阈值见验收表。 | 左中为图像塔forward；右为双塔934条测试；非系统端到端加速证据。 |
| [09_历史查询分模式参考](09_历史查询分模式参考.png) | 历史AI试点检索指标可复算，但不能证明本轮TRT端到端效果。 | 仅历史排序复算；未调用微调/TRT查询编码器；AI标签不是独立人工真值。 |

01–04、08用于报告的推理加速与一致性部分；05、07用于模型规模/文件体积表；06用于数据特点与基线难度分析；09只能作为历史端到端参考，不能标为优化后的结果。

图04是后端×指标误差热力图；图06是9类FP32基线热力图。由于源凭证不含TRT分类别结果，不生成9类TRT损失热力图。

图中不绘制置信区间，因为源文件只有一次20次计时的汇总。P90仍保留在表格中，可用于描述同轮尾延迟。
