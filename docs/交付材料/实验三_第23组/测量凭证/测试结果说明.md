# 实验三推理加速评测结果（杜军博任务交付）

本轮目录：exp3_inference_acceleration_20261025。生成日期：2026-10-25T20:03:36+08:00。

## 1. 执行范围与数据来源

用户确认沿用队友已经核验的训练机结果。本轮实际执行的是：读取凭证、重新计算加速比与验收条件、复算历史查询指标、导出表格与论文图。本轮没有加载模型、重新导出 ONNX、发起 API 调用或新增 GPU 测速。

当前主任务是 3.1.4 ONNX + TensorRT 推理加速，兼顾 3.2.1 计算图优化。INT8、4-bit、剪枝均不在本轮执行范围内；历史量化结果仍在 docs/optimize/ 中留档。

原始测量的预热/正式次数逐组保存在 tables/runtime_comparison.csv，本轮为预热10次、计时20次。中位数为主，P90为描述性尾延迟；没有多轮独立实验的置信区间。统计对象是图像塔 forward，不含预处理、FAISS、商品过滤、重排、网络和界面。精度数据则来自双塔文搜图测试：934 条查询，候选池 934。

## 2. 速度结果

| 后端 | 批次 | PyTorch/ms | 引擎/ms | 加速/倍 | 延迟降低/% | 吞吐提升/% |
|---|---|---|---|---|---|---|
| ORT-CPU | 1 | 90.56 | 85.24 | 1.062 | 5.87 | 6.36 |
| ORT-CPU | 32 | 2532.61 | 2554.38 | 0.991 | -0.86 | -0.79 |
| ORT-CUDA | 1 | 4.98 | 4.54 | 1.097 | 8.84 | 9.81 |
| ORT-CUDA | 32 | 50.90 | 54.55 | 0.933 | -7.17 | -6.70 |
| TensorRT | 1 | 4.59 | 1.94 | 2.366 | 57.73 | 136.58 |
| TensorRT | 32 | 50.43 | 23.84 | 2.115 | 52.73 | 111.52 |

各行使用其自身文件内的 PyTorch 对照。CPU线程数对齐；GPU采用各组配对的同精度基线，不能拿CPU和GPU绝对耗时计算加速比。ORT-CUDA本轮按JSON为 1.097× / 0.933×；本文统一使用已归档JSON，而不使用旧文档的手填数值。

计算公式：加速比 = PyTorch 中位延迟 / 引擎中位延迟；延迟降低 = (1 − 引擎延迟 / PyTorch 延迟) × 100%；吞吐提升 = (引擎吞吐 / PyTorch 吞吐 − 1) × 100%。吞吐使用原记录已经四舍五入的 samples/s，因此与单纯由延迟反推的百分比可能有小数尾差。

## 3. 双塔精度一致性

| 后端 | R@1/% | R@5/% | R@10/% | ΔR@1/pp |
|---|---|---|---|---|
| PyTorch FP32 | 58.5653 | 89.2934 | 96.6809 | +0.0000 |
| ORT-CPU FP32 | 58.5653 | 89.2934 | 96.6809 | +0.0000 |
| TensorRT FP16 | 58.1370 | 89.2934 | 96.5739 | -0.4283 |

共同基线来自自研评测的PyTorch FP32，R@1 = 58.5653%，不能混用实验二官方脚本的58.67%。TensorRT FP16的净差为 -0.4283pp，约相当于 934 条中的 4 条Top-1净命中差；现有凭证没有逐样本配对排名，不能据此说明到底多少条查询发生变化，也不能把所有差异归因于某一个算子或FP16本身。

现有后端精度凭证没有 MRR/nDCG 或 TensorRT 分类别排名，本文不从 R@K 推造这些指标。9 类图只展示已有 FP32 基线的类别分布，不代表 TensorRT 的各类别损失。

## 4. 验收结果

| 任务 | 项目 | 实测 | 目标 | 判定 |
|---|---|---|---|---|
| 3.1.4 | 延迟降低 batch=1 | 57.7342 % | >= 40 % | 通过 |
| 3.1.4 | 吞吐提升 batch=1 | 136.5764 % | >= 50 % | 通过 |
| 3.2.1 | 计算图加速比 batch=1 | 2.3660 倍 | >= 1.2 倍 | 通过 |
| 3.1.4 | 延迟降低 batch=32 | 52.7266 % | >= 40 % | 通过 |
| 3.1.4 | 吞吐提升 batch=32 | 111.5209 % | >= 50 % | 通过 |
| 3.2.1 | 计算图加速比 batch=32 | 2.1154 倍 | >= 1.2 倍 | 通过 |
| 3.1.4 | 模型级 R@1 绝对差 | 0.4283 pp | <= 1 pp | 通过 |
| 3.2.1 | 模型级 R@1 绝对差 | 0.4283 pp | <= 0.5 pp | 通过 |

3.1.4 的速度项在图像塔 forward 范围内满足目标，双塔整体 R@1 差满足 ≤1pp。3.2.1 按本轮明示口径（加速比 ≥1.2、R@1 差 ≤0.5pp）满足目标。上述结论不等同于 132 查询端到端延迟也降低 40%，也不能说明文本塔单独达到同样加速。

## 5. 模型规模与文件大小

两个塔共 188,262,912 个参数、42.6299 GFLOPs（图像 33.6963G、文本 8.9337G）。FLOPs为batch=1，图像224×224、文本长度52，只计MatMul/Conv，不包含全部算子。整模型权重还含一个logit_scale标量，因此历史体积报告中的参数量多1。

export_report_fp32 / fp16在队友执行中被最后导出的文本塔覆盖，因此它们只能证明文本塔ONNX的 389.58 / 194.97 MiB；不能拿它们当成双塔总大小。纯权重FP32/FP16大小另取已核验quantize_report的文件字节，约 718.29 / 359.21 MiB。图表分别标明文件对象，文件大小也不等于峰值显存。推理加速不修改架构，本轮不宣称参数量或理论FLOPs下降。
