## 2. 逐项说明

### 2.1 `encoder.py`（核心）

```python
def __init__(..., quant: str = "none") -> None:
    ...
    self.quant = (quant or "none").strip().lower()
    ...
    self.model.eval()
    self._apply_quant()          # ← 加载完、用之前，按需转换精度
```

`_apply_quant()` 的行为：

| quant | 做什么 | 限制 |
|---|---|---|
| `none` / `""` | 保持官方默认加载（注意 `create_model()` 会转 FP16，实际是 FP16） | — |
| `fp32` | `model.float()`，真正的 FP32（精度参照） | — |
| `int8` | `quantize_dynamic(model, {nn.Linear})`，整层一个缩放系数 | **只能 CPU** |
| `int8-pc` | 同上但按输出通道量化（`per_channel_dynamic_qconfig`） | **只能 CPU** |
| `int8-text` | 只量化文本塔（`bert.` 前缀，72 个 Linear） | **只能 CPU** |
| `int8-visual` | 只量化图像塔（`visual.` 前缀，24 个 Linear） | **只能 CPU** |
| `fp16` | `model.half()` | **只能 CUDA**，CPU 上多数算子不支持 half |
| 其他 | `ValueError` | — |

后两个模式用自写的 `_replace_dynamic_linear(model, predicate)` 实现——官方 `quantize_dynamic()` 只能按”模块类型”整棵树替换，无法按名字挑层。它逐层 `DynLinear.from_float()`，前提是先给模块赋 `qconfig`（否则原样返回）。

另外 `model_tag` 会带上精度后缀，日志和注册表里能直接看出用的是哪一档：

```
ViT-B-16+epoch3.pt            ← FP32
ViT-B-16+epoch3.pt@int8       ← INT8
ViT-B-16+epoch3.pt@fp16       ← FP16
```

**不做会怎样**：没法按精度跑模型，实验三的精度损失、加速对比全部无从谈起。

### 2.2 `build_category_index.py`

三处改动：

1. 新增 `--quant {none,fp16,int8}`（默认 `none`）；
2. 传给编码器，并写进 `index_registry.json` 的 `model.quant`、以及每个类别的 `build_report.json`；
3. 校验已有索引：`name` / `checkpoint` / **`quant`** 三者任一不同就报错，要求换 `--output-dir`。

```python
if existing_quant != quant:
    raise RuntimeError(
        f"已有索引用精度 {existing_quant}，与本次 {quant} 不同；"
        "不同精度的向量不能混用，请使用新的 --output-dir。")
```

**不做会怎样**：注册表里没有精度信息，查询侧无法判断该用哪种编码器；混建时也不会报错。

### 2.3 `search_category_index.py`

新增 `--quant`，**留空时读注册表**：

```python
quant = (args.quant or model_config.get("quant", "none") or "none").strip().lower()
```

设计意图：正常使用不要手动传，让它跟着索引走；只有排查问题时才手动覆盖。

### 2.4 `evaluate_retrieval.py`

只加 2 行，`checkpoint` 那套写法原样复制：

```python
quant = (model_config.get("quant", "none") or "none").strip().lower()
...
encoder = ChineseClipEncoder(..., checkpoint=checkpoint, quant=quant)
```

**为什么不改不行**：端到端评测（132 条 pilot 查询）要自己构造编码器去查索引。如果索引是 INT8 建的、编码器却按 FP32 加载，相似度矩阵对不上，**不报错但指标全错**。

### 2.5 `scripts/optimize/quantize.py` 与 `eval_quant.py`

把 `epoch3.pt` 落盘成三份并量体积：

| mode | 产物 | 用途 |
|---|---|---|
| `fp32w` | 纯 FP32 权重 | 体积基准（100%） |
| `fp16` | 半精度 | 对照 |
| `int8` | 动态量化模块 | 达标项 |

两处关键实现（都是踩坑后加的）：

```python
model.float()   # create_model() 默认把权重转 FP16，不转回来会得到"假 FP32"
```

```python
quantize_dynamic(model, {torch.nn.Linear}, dtype=torch.qint8)  # 只覆盖 Linear
```

产物写到 `data/optimize/<RUN_ID>/quantized/`，并把 `quantize_report.json` **自动复制一份**到
`docs/optimize/runs/<RUN_ID>/` 作为入库凭证。单跑某个 mode 时会与已有报告**合并**，不会覆盖掉其他组。

`eval_quant.py` 负责精度评测（P3）：同一批 934 道题（`test_texts.jsonl` + `lmdb/test` 里的 base64 图片），
在指定精度下重新编码、算相似度、输出 R@1/R@5/R@10。三点实现说明：

1. **为什么不用官方 `extract_features.py`**：它走 `load_from_name()`，加载不了动态量化模块（packed params 不是标准 state_dict）。
2. **图片从 lmdb 直接解码**，不落临时文件。
3. 结果按精度分文件（`test_<quant>.json`），**跑新的一组不会覆盖旧的**，并同样自动复制到 `docs/optimize/runs/<RUN_ID>/accuracy/`。

### 2.7 `configs/retrieval.json`

两个 section 各加一行 `"quant": "none"`。

注意这是**可选**的，因为 `scripts/retrieval/configuration.py` 的校验是**单向**的：

| 情况 | 结果 |
|---|---|
| JSON 里有 key，但脚本没有对应 `--参数` | ❌ 报错「不支持的字段」 |
| 脚本有 `--quant`，JSON 里没写 | ✅ 不报错，用 argparse 默认值 |

加它的理由是让 JSON 与 CLI 对称，且 `retrieval_exp3_*.json` 正是从这个文件复制改的。

### 2.8 `configs/retrieval_exp3_{fp16,int8}.json`

| 配置 | 索引目录 | quant | device |
|---|---|---|---|
| `retrieval_exp3_fp16.json` | `data/index_data_exp3_fp16` | `fp16` | `cuda` |
| `retrieval_exp3_int8.json` | `data/index_data_exp3_int8` | `int8` | **`cpu`** |

建量化索引 = 用这两份配置跑 `build_category_index.py`，再用 `evaluate_retrieval.py` 做端到端评测。

## 3. 同源原则：为什么 1–4 必须一起改

```
建索引（build）  → 写 registry.model.quant
查询（search）   → 读 registry.model.quant
端到端评测（eval）→ 读 registry.model.quant
```

三者读同一个来源，才不会出现"用 A 精度编码、用 B 精度查"。这是实验三最容易出错、且**不会报错**的一类 bug，所以校验和默认读取都要写死在代码里，而不是靠人记。

## 4. 向后兼容

- 老索引（`data/index_data/`、`data/index_data_finetuned/`）的注册表里**没有 `quant` 字段** → 读出来默认 `"none"` → 行为与改动前完全一致。
- 不传 `--quant` 时，建索引的默认精度也是 `none`，现有流程不受影响。
- `encoder.py` 的 `quant` 是**带默认值的关键字参数**，原有调用方无需改动。
