## 二、完整流程（首次约 30-40 分钟，其中 20 分钟是下载）

### 第 0 步：确认环境

```bash
# 必须有 NVIDIA 驱动 + CUDA
nvidia-smi
# 期望看到 RTX 5060，显存 8GB 左右

# Python 3.10+
python --version
```

**如果 `nvidia-smi` 报错**：先装显卡驱动，后面全部不用做。

### 第 1 步：拉代码

```bash
git clone https://github.com/serendip215-cell/Agent_ShopVision.git
cd Agent_ShopVision
git log --oneline -1
# 期望看到 5.3 相关提交（5ca15581d 或更新）
```

**确认适配器在里面**（这一步很关键，没有就跑不了）：

```bash
ls -lh dist/lora_adapter_v2/
# 必须看到 adapter_model.safetensors，约 63MB
```

如果这个目录是空的或不存在，说明你拉的代码太旧，先 `git pull`。

### 第 2 步：装依赖

建议开虚拟环境，避免污染系统 Python：

```bash
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Linux:    source .venv/bin/activate

pip install -U pip
pip install torch --index-url https://download.pytorch.org/whl/cu124
pip install transformers peft accelerate bitsandbytes modelscope
```

**版本要求**（低版本会报错）：

| 包 | 最低版本 | 为什么 |
|---|---|---|
| transformers | ≥4.46 | Qwen3 支持 |
| peft | ≥0.13 | LoRA 加载 |
| bitsandbytes | ≥0.44 | 4-bit 量化（8G 卡必须用） |
| modelscope | 任意 | 下载基座模型 |

装完自查：

```bash
python -c "import torch, transformers, peft, bitsandbytes; print('torch', torch.__version__, 'cuda', torch.cuda.is_available())"
# 必须打印 cuda True
```

**如果 `cuda False`**：torch 装成 CPU 版了，重装上面那条 `--index-url` 的命令。

### 第 3 步：下载基座模型（约 8GB，最慢的一步）

**不要用 HuggingFace，国内下不动。** 用 ModelScope：

```bash
python -c "from modelscope import snapshot_download; print(snapshot_download('Qwen/Qwen3-4B-Instruct-2507', cache_dir='models'))"
```

会打印一个路径，类似 `models/models/Qwen--Qwen3-4B-Instruct-2507/snapshots/master`。
**把这个路径记下来**，下一步要用。

预计 10-20 分钟（实测 9 分 17 秒，5-19MB/s 波动）。可以去喝杯水。

### 第 4 步：跑评测（要跑**两次**）

**2026-11-08 更新**：第一次实测是 2/10 = 20%，根因是训练数据里类目是明写的
（「限制在X类」），模型没学过从口语推断类目。已加确定性后处理层
（`scripts/agent/category_map.py`）。所以现在要跑**两次**做对比。

#### 4-A 纯模型基线（不加后处理）



把上一步的路径填进去：

```bash
python scripts/agent/eval_tool_accuracy.py \
    --mode model \
    --model <上一步打印的路径> \
    --adapter dist/lora_adapter_v2
```

Windows PowerShell 里换行符不同，写成一行也行：

```powershell
python scripts/agent/eval_tool_accuracy.py --mode model --model models\models\Qwen--Qwen3-4B-Instruct-2507\snapshots\master --adapter dist\lora_adapter_v2
```

#### 4-B 混合方案（模型 + 规则后处理，生产环境实际行为）

```bash
python scripts/agent/eval_tool_accuracy.py \
    --mode model \
    --model <上一步打印的路径> \
    --adapter dist/lora_adapter_v2 \
    --hybrid
```

后处理做两件事：规范化 query（去掉「找」「有没有」等指令词）+ 用关键词映射补类目。

#### 结果怎么用

| 命令 | 用途 | v2 预期值 | 报告里怎么称呼 |
|---|---|---|---|
| 4-A（不加 `--hybrid`） | 纯模型能力 | **9/10 = 90%** | 「微调模型基线」 |
| 4-B（加 `--hybrid`） | 生产环境实际效果 | **10/10 = 100%** | 「模型 + 规则后处理」 |

**两个数字都要发回来，缺一不可。** 报告里必须区分表述。

**v2 的意义**：纯模型 90% 已经达标，不靠后处理。
v1 是纯模型 10% + 后处理补到 100%，那不算模型能力。
详见 `09-5.3优化实跑：扩充数据重训.md`。

#### 期望输出

**这会输出 10 轮评测结果**，类似：

```
==============================================================
工具调用准确率（model 模式，10 轮）
==============================================================
✓ # 1  帮我找黑色木纹手机壳，5个
✓ # 2  我想找白色运动鞋
✗ # 3  推荐3个蓝色运动水杯   失败项: query
...
--------------------------------------------------------------
命中 9/10 = 90%   目标 ≥90% → 达标
  工具名      10/10 = 100%
  query       9/10 = 90%
  类目        9/10 = 90%
  top_k      10/10 = 100%
```

## 三、如果报错怎么办

| 报错 | 原因 | 解决 |
|---|---|---|
| `CUDA out of memory` | 8G 显存不够 | 加 `--no-4bit` 反而更费显存，**不要加**。改用：`export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 再跑 |
| `bitsandbytes 不是有效的 Win32 程序` | Windows 装 bitsandbytes 有坑 | 先 `pip uninstall bitsandbytes`，然后 `pip install bitsandbytes-windows` 或改用 WSL |
| `Can't load the configuration` | 模型路径写错了 | 确认 `--model` 指向的目录里有 `config.json` |
| `peft` 版本冲突 | 版本太低 | `pip install -U peft` |
| 下载卡在 0% | ModelScope 网络问题 | 重试，或换 `pip install modelscope -U` |

**Windows 用户特别注意**：`bitsandbytes` 在原生 Windows 上支持不好。
如果装不上或报错，**直接用 WSL**：

```bash
wsl
cd /mnt/<盘符>/<你的路径>/Agent_ShopVision
# 然后按第 2 步重装依赖（Linux 版）
```

## 六、附：如果你想顺便验证适配器单独能用

跑完评测后，可以再确认一次适配器加载（这条不需要跑评测那么久）：

```bash
python -c "
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import PeftModel
import torch

base = 'models/models/Qwen--Qwen3-4B-Instruct-2507/snapshots/master'  # 换成你的路径
qc = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type='nf4',
                        bnb_4bit_compute_dtype=torch.bfloat16, bnb_4bit_use_double_quant=True)
tok = AutoTokenizer.from_pretrained(base)
model = AutoModelForCausalLM.from_pretrained(base, quantization_config=qc, device_map='auto')
model = PeftModel.from_pretrained(model, 'dist/lora_adapter_v2')
model.eval()
print('✅ 适配器加载成功')

# 试一条推理
msgs = [{'role':'user','content':'把用户需求转换为白名单检索工具调用参数，只输出 JSON。白名单工具：text_search\n\n找白色运动鞋'}]
prompt = tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True, enable_thinking=False)
inputs = tok(prompt, return_tensors='pt').to(model.device)
with torch.inference_mode():
    out = model.generate(**inputs, max_new_tokens=100, do_sample=False)
print(tok.decode(out[0][inputs['input_ids'].shape[1]:], skip_special_tokens=True))
"
```

**期望输出**：类似 `{"tool":"text_search","arguments":{"query":"白色运动鞋","category":"鞋","top_k":5}}`

> 注意：模型有可能输出 `tool_search` 而不是 `text_search`（这是已知问题，
> `intent_parser.closest_tool()` 会自动纠错）。看到 `tool_search` 不用慌，评测脚本会处理。
