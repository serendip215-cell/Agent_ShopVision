# 5.4 对话 Agent 训练规范（v3）

> 读者：负责训练 LoRA 的同学 / 训练 AI。
> 目标：把只会「输出一次搜索调用」的 v2 适配器，升级成**会对话、会选工具、会给结果点评**的 v3。
> 产物：`dist/lora_adapter_v3/`（约 64 MB），替换 v2 即可，**基座和索引都不用动**。

---

## 一、要训练出什么能力

| 能力 | 例子 | 期望输出 |
|---|---|---|
| 调工具 | 「找一双白色运动鞋」 | `text_search` + 参数 |
| 按图搜 | 「按这张图找类似的」 | `image_search` |
| 列类目 | 「你们能搜哪些类」 | `list_categories` |
| 查详情 | 「第二个什么材质」 | `get_item_detail` + item_id |
| 直接对话 | 「你好」「你能干嘛」 | `reply`，不检索 |
| 澄清 | 「随便看看」 | `reply` 反问想看哪类 |
| 结果点评 | 拿到检索结果后 | `reply`，60–120 字，只引用给定字段 |

**能力边界（写进报告也用这套口径）**：模型是纯文本，不“看图”；图像能力由图像塔提供。没有价格/销量数据，不许编造。

---

## 二、输出协议（训练与推理必须一致）

模型每次**只输出一个 JSON**，不加解释、不加 Markdown 代码块：

```json
{"action":"tool","tool":"text_search","arguments":{"query":"白色运动鞋","category":"鞋","top_k":5}}
{"action":"tool","tool":"image_search","arguments":{"alpha":0.6}}
{"action":"tool","tool":"list_categories","arguments":{}}
{"action":"tool","tool":"get_item_detail","arguments":{"item_id":"muge_916"}}
{"action":"reply","text":"这类高帮鞋更适合秋冬日常穿。"}
```

### 可选字段 `say`（只允许出现在 tool 上）

```json
{"action":"tool","tool":"text_search","arguments":{"query":"白色运动鞋","category":"鞋","top_k":5},"say":"我先帮你找找白色运动鞋"}
```

- 一句话、≤30 字、口语；
- **不得**出现商品名、价格、数量结论（“找到 3 件”也不行，因为还没搜）；
- 后端只把它当过渡气泡，不参与结果。

### 硬约束

1. `tool` 必须是 `text_search` / `image_search` / `list_categories` / `get_item_detail` 之一；
2. `reply` 的 `text` 非空，且不得包含价格、销量、优惠；
3. 不允许一条输出里同时有 `tool` 和 `text`（`say` 除外）；
4. 不确定时用 `reply` 说明或反问，**不要猜工具**。

---

## 三、数据格式

沿用 v2 的 SFT 格式，每行一条：

```json
{"messages":[
  {"role":"system","content":"<系统提示词，见下>"},
  {"role":"user","content":"找一双白色运动鞋"},
  {"role":"assistant","content":"{\"action\":\"tool\",\"tool\":\"text_search\",\"arguments\":{\"query\":\"白色运动鞋\",\"category\":\"鞋\",\"top_k\":5},\"say\":\"我先帮你找找\"}"}
]}
```

**系统提示词**（训练与推理共用，脚本里叫 `SYSTEM_PROMPT`）：

```
你是电商导购助手。可用工具：
- text_search(query, category?, top_k)：按文字找商品
- image_search(alpha)：按用户上传的图片找相似商品
- list_categories()：列出可检索的类目
- get_item_detail(item_id)：查某个商品详情
只输出一个 JSON：{"action":"tool","tool":...,"arguments":{...}} 或 {"action":"reply","text":"..."}。
需要检索才调工具；闲聊、追问、能力介绍一律 reply。
reply 只能引用给定信息，不得编造价格、销量、品牌。可加 "say" 说明你要做什么。
```

### 一条“结果点评”样本（多轮同构）

```json
{"messages":[
  {"role":"system","content":"<同上>"},
  {"role":"user","content":"用户想要白色运动鞋，检索结果：\n{\"items\":[{\"item_name\":\"高帮鞋男欧货\",\"type\":\"高帮运动鞋\",\"color\":\"白色\",\"material\":\"未识别\",\"similarity\":0.47}]}\n请基于以上字段写 60-120 字的点评。"},
  {"role":"assistant","content":"{\"action\":\"reply\",\"text\":\"这几款都是白色系，以前两款高帮为主，偏休闲；材质大多未标注，只有第二款标了真皮。\"}"}
]}
```

### 反面样例（判失败）

```json
{"action":"reply","text":"这双鞋售价 199 元，销量很好。"}          ← 编造价格/销量
{"action":"tool","tool":"text_search","arguments":{"query":"鞋"}}   ← 什么都没说就搜
{"action":"tool","tool":"text_search","text":"找到了 3 件"}          ← 混合输出
```

## 四、数据配比（共 440 条）

| 类型 | 条数 | 说明 |
|---|---:|---|
| `text_search` | 120 | 类目**不明写**，让模型自己推；60 条带 `say` |
| `image_search` | 40 | 「按这张图找类似的」 |
| `list_categories` | 20 | — |
| `get_item_detail` | 20 | 指代上一轮商品 |
| 结果点评 | 120 | 输入含检索结果 JSON |
| 对话 reply | 90 | 问候 / 能力 / 常识 / 拒答 |
| 澄清 | 30 | 「随便看看」→ 反问 |

> 建议先跑 100 条验证协议能学会，再补满 440 条。

---

## 五、数据从哪来（不用手写）

**用生成脚本**：

```bash
python scripts/agent/build_dialogue_sft.py --out data/agent/sft_v3
```

它做三件事：

1. 从 `data/index_data_finetuned/*/items.csv` 读真实商品字段（名称/细分类/颜色/材质），生成「结果点评」样本；
2. 用模板生成工具调用、对话、澄清样本；
3. 按 90/10 切分，写 `train.jsonl` / `valid.jsonl` / `manifest.json`。

参数：

| 参数 | 默认 | 作用 |
|---|---|---|
| `--out` | `data/agent/sft_v3` | 输出目录 |
| `--seed` | `20261109` | 随机种子（可复现） |
| `--limit` | `440` | 总条数 |
| `--dry-run` | 关 | 只打印统计，不写文件 |

生成后**必须人工抽查 20 条**：点评是否只引用了字段、`say` 是否超 30 字、有无价格。

## 六、训练配置

| 项 | 值 |
|---|---|
| 基座 | `Qwen/Qwen3-4B-Instruct-2507`（4bit QLoRA） |
| 方法 | LoRA r=16 / alpha=32 / dropout=0.05 |
| epoch | 2 |
| lr | 1e-4，cosine |
| batch | 1 + 梯度累积 8 |
| max_len | 512 |
| 验证集 | 生成脚本自动留 10% |
| 产物 | `dist/lora_adapter_v3/` |

复用 `scripts/agent/finetune/train_lora.py`，把数据目录指向 `data/agent/sft_v3`。

## 七、训练前自查（逐条打勾）

```bash
python scripts/agent/build_dialogue_sft.py --dry-run
```

- [ ] 各类条数与上表一致；
- [ ] 每条 assistant 内容都是**合法 JSON**（脚本会校验，不合法直接报错）；
- [ ] 没有一条 `reply` 里出现「元 / 价格 / 销量 / 折扣」；
- [ ] `say` 全部 ≤30 字；
- [ ] 训练集和验证集没有完全重复的行（脚本按内容去重）。

## 八、训练后怎么检验（必须三步都做）

### 1. 离线自动评测（40 条）

```bash
python scripts/agent/eval_v3_dialogue.py --model models/models/Qwen--Qwen3-4B-Instruct-2507/snapshots/master --adapter dist/lora_adapter_v3
```

输出逐条结果 + 汇总，并写 `data/agent/eval_v3_dialogue.json`。

| 指标 | 阈值 | 说明 |
|---|---|---|
| JSON 可解析率 | ≥95% | 解析失败直接算错 |
| action 判断正确 | ≥36/40 (90%) | tool vs reply |
| 工具名正确 | ≥90% | 只看 action=tool 的样本 |
| 参数正确 | ≥90% | query/category/top_k/alpha |
| 回复不含价格/销量 | 100% | 正则扫描 |
| 点评只引用给定字段 | 抽查 10 条全过 | 人工 |

### 2. 回归（不能退步）

```bash
python scripts/agent/eval_tool_accuracy.py --mode model --model models/models/Qwen--Qwen3-4B-Instruct-2507/snapshots/master --adapter dist/lora_adapter_v3
```

v2 是 **9/10 = 90%**，v3 不得低于 9/10。低了说明新数据把旧能力冲掉了，需要调整配比（减少对话样本或加回原 tool 样本）。

### 3. 端到端（最后一道）

起后端 → 打开 `/agent` → 依次试：

1. 「找一双白色运动鞋」→ 有 `say` 过渡 + 卡片 + 点评；
2. 「你好」→ 直接回话，不检索；
3. 「随便看看」→ 反问类目；
4. 上传图 → 「这双适合跑步吗」→ 先图搜，再基于结果回答。

记录：`thinking` 内容、点评是否和卡片一致、响应耗时（P95 < 5 秒）。

## 九、上线切换（3 步）

1. 把 `dist/lora_adapter_v3/` 提交进 git（与 v2 同规则，`.gitignore` 已放行 `dist/lora_adapter*`）；
2. 后端 `webapp/backend/app/config.py` 的 `agent_adapter` 指向 v3（或改 `.env` 的 `SHOPVISION_AGENT_ADAPTER`）；
3. 重启 uvicorn，看日志 `agent 意图模型就绪`，再发一句话验证。

**回滚**：把 adapter 指回 `dist/lora_adapter_v2` 即可，10 秒完成。

## 十、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 输出带 Markdown ```json | 训练数据里混了代码块 | 数据清洗，assistant 只留裸 JSON |
| 所有输入都回 `text_search` | 工具样本里 `reply` 太少 | 把 reply 占比提到 20% 以上 |
| 点评里出现库里没有的材质 | 点评样本的输入字段被模型“补全” | 抽查数据：输入必须只含真实字段 |
| 准确率 90% 但答非所问 | 只学了格式没学语义 | 增加同类不同说法（同义改写） |
| 4bit 训练 OOM | batch 太大 | batch=1 + 累积 8，max_len 512 |
