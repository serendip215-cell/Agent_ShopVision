# 5.3 优化实跑：扩充训练数据 + 重训 LoRA

> 2026-11-08。针对「纯模型准确率只有 10%」的问题，按 ZXCcs231 优化方案
> 第二、三阶段执行：**扩充 tool_call 训练数据 → 重新微调**。
>
> 结论先行：**纯模型 10% → 90%，类目 10% → 100%，已达标且不依赖后处理。**

## 一、问题回顾

| 版本 | 训练数据 | 纯模型准确率 | 类目 |
|---|---|---:|---:|
| v1（原） | tool_call 15 条，**全部明写类目** | 10% | **10%** |
| v2（本次） | tool_call **78 条，不写类目** | **90%** | **100%** |

**v1 的根本缺陷**：5.1 生成的 tool_call 样本 15/15 都是

```
帮我搜索XXX，限制在X类，返回N个结果
        ↑ 类目明写在句子里，模型只要照抄
```

模型学到的是「抽取句中已给的类目」，而不是「从商品名推断类目」。
所以在口语评测集上，类目准确率只有 10%。

v1 靠 `category_map` 规则后处理把总分拉到 100%，但**模型本身没变强**。
这不是真正的优化。

## 二、这次的改动：让训练数据里没有类目

新增 `scripts/agent/finetune/build_tool_call_expanded.py`。

### 数据来源

`data/processed_data_cleaning` 的真实商品（9,393 条），字段：
`item_name` / `type`（细分类）/ `color` / `material`。

### 关键设计

**1. query 里不能有类目名**

构造 query 只用「颜色 + 细分类 + 商品名片段」，并**自检**：
用 `category_map.infer_category` 反向推断，必须能推断回原类目才保留。
推断不出来的样本直接丢弃——保证训练数据本身是「可从商品名推断的」。

**2. 句式多样化（15 种模板，都不含「限制在X类」）**

```
{query}
我想找{query}
帮我找{query}
有没有{query}
推荐{query}
{query}，要{top_k}个
推荐{top_k}个{query}
{query}多少钱
...
```

**3. 覆盖 9 个类目 + 无类目兜底**

每类 8 条，共 72 条；加 6 条无类目兜底（「随便看看有什么」等，
期望输出不含 `category`），合计 **78 条**。

**4. 保留原有 attribute / intent 数据**

只替换 tool_call，其余 85 条原样保留，避免破坏其他任务能力。

### 生成结果

```
鞋 8 / 水杯 8 / 包 8 / 男装 8 / 运动服 8 / 女装 8 /
手机壳 8 / 厨房用品 8 / 家居用品 8 / 无类目 6
tool_call: 78 条（原 15 条）
总计: 163 条
含「限制在X类」明写类目的样本: 0/78  ← 关键
```

样本示例：

| 输入 | 输出 |
|---|---|
| 找一下白色 儿童家居拖鞋 宝宝家用拖鞋4岁 | `{"tool":"text_search","arguments":{"query":"白色 儿童家居拖鞋 宝宝家用拖鞋4岁","category":"鞋","top_k":5}}` |
| 黑色 深煎锅多少钱 | `{"query":"黑色 深煎锅","category":"厨房用品","top_k":10}` |
| 随便看看有什么 | `{"query":"随便看看有什么","top_k":5}`（无 category） |

## 三、重训配置

```bash
python scripts/agent/finetune/train_lora.py \
  --model Qwen/Qwen3-4B-Instruct-2507 \
  --train-file data/agent/sft_expanded/train.jsonl \
  --valid-file data/agent/sft_expanded/valid.jsonl \
  --output runs/5.2_lora_v2 \
  --epochs 5 --batch-size 2 --grad-accum 8 \
  --lr 1e-4 --lora-r 16 --lora-alpha 32
```

| 项 | 值 |
|---|---|
| 数据 | train 153 条 / valid 10 条 |
| 机器 | AutoDL RTX 3080 Ti 12G |
| epoch | 5（比 v1 的 3 多，因为数据翻倍需要更多步数） |
| 其余超参 | 与 v1 完全一致（保证可比） |
| 耗时 | 约 4 分钟 |

**产出独立目录** `dist/lora_adapter_v2/`，不覆盖 v1，便于对比。

## 四、实测结果（RTX 3080 Ti 12G，真跑推理）

### 纯模型（不加任何后处理）

| 项 | v1 | **v2** | 变化 |
|---|---:|---:|---:|
| 总体 | 1/10 = 10% | **9/10 = 90%** | **+80pp** |
| 工具名 | 100% | 100% | — |
| query | 70% | **90%** | +20pp |
| **类目** | **10%** | **100%** | **+90pp** |
| top_k | 100% | 100% | — |

**纯模型 90% 已达标，不依赖任何规则后处理。** 这是真正的模型能力提升。

唯一失败：#5「有没有灰色的双肩包」，模型输出 query `灰色的双肩包`，
gold 是 `灰色 双肩包`（差一个「的」）。

### 加后处理

| 项 | v2 + 后处理 |
|---|---:|
| 总体 | **10/10 = 100%** |
| 四项 | 全 100% |

后处理在这版只修了 #5 那一个「的」。

## 四之二、跨机器复验（RTX 5060 8G，演示机）

杜军博 在演示机上跑同一套命令，结果与 3080Ti 完全一致：

| 机器 | 纯模型 | 加后处理 | 失败项 |
|---|---:|---:|---|
| RTX 3080Ti 12G | 9/10 = **90%** | 10/10 = 100% | #5 |
| **RTX 5060 8G** | 9/10 = **90%** | 10/10 = **100%** | #5 |

**失败的都是同一条**：#5「有没有灰色的双肩包」，
模型输出 query `灰色的双肩包`，gold 是 `灰色 双肩包`（差一个「的」）。

这点很重要：
1. v2 模型**跨机器稳定**，不是某台机器的偶然结果
2. v1 曾经出现过跨机器漂移（5060 是 20%、3080Ti 是 10%），v2 没有这个问题
   —— 说明扩充数据后模型的输出更确定

凭证：`data/agent/eval_5060_v2_base.json`、`eval_5060_v2_hybrid.json`（含终端日志）。

## 五、与 v1「100%」的本质区别

| | v1 的 100% | v2 的 100% |
|---|---|---|
| 纯模型 | 10% | **90%** |
| 后处理贡献 | +90pp（几乎全靠规则） | +10pp（只修一个「的」） |
| 报告能否说「模型学会了」 | ❌ 不能 | ✅ **可以** |

**这才是优化。** v1 是靠规则补出高分，模型没变；v2 是模型真的学会了推断类目。

## 六、过程中的两个发现

### 1. 「T恤」的类目标注有歧义

#9「找一下白色T恤」，gold 标「女装」，但库里男装/女装/运动服都有 T 恤。
模型判「男装」被判为错误——这是标注造成的假失败。

已给评测集加 `category_accept` 字段，允许「女装/男装/运动服」任一：

```python
"arguments": {"query": "白色 T恤", "category": "女装",
              "category_accept": ["女装", "男装", "运动服"], "top_k": 5}
```

**这是 5.1 数据标注要改的地方**：单一类目标注对跨类目商品不公平。

### 2. safe 模式后处理

v2 的后处理从「一律清洗 query」改成「只在检测到指令词/数量词时才清洗」，
避免规则过度干预。这样模型答对的部分就真的是模型答对的。

## 八、报告怎么写

**主结论**：

> 扩充 tool_call 训练数据（15 → 78 条，且训练输入不再明写类目）并重训后，
> 纯模型工具调用准确率从 **10% 提升到 90%**，其中类目识别从 **10% 提升到 100%**，
> 达到任务书 ≥90% 的要求。加上确定性后处理（query 规范化）后达到 100%。

**可以写**：模型学会了从商品名推断类目。

**不要写**：v1 那版「后处理后 100%」当成模型能力。

**顺带可写的工程反思**：
- 训练数据模板决定了模型能力边界（明写类目 → 只会照抄）
- 评测集标注要考虑跨类目商品（T 恤归属）
- 同一模型换机器跑，基线会漂（5060 是 20%，3080Ti 是 10%），报告要注明机器
